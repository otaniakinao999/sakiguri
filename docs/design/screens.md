```

┌ Sidebar inset (p-2 = 8px) ┐┌ Main ───────────────────────────────┐
│ ┌ SideNav 224px ────────┐ ││ PageHeader（ダッシュボード以外）      │
│ │ bg-primary rounded-lg │ ││ Content: pt-6 px-8 pb-8, gap-6       │
│ └───────────────────────┘ ││   Panel（bg-card rounded-lg p-6）…   │

```

- **画面幅：** デザインは 1440px で作っています。最小は 1280px を想定し、Main は可変幅です。
- **サイドバー：** 画面の高さに合わせて `sticky top-0 h-screen` で固定します。Main だけがスクロールします。
- **パネルの並べ方：**
  - パネル同士の間隔は 24px（`gap-6`）。
  - 2カラムにする画面では、右カラムを固定幅（例：口座・カード 420px）、左カラムを `flex-1` にします。
- **数値の列：** すべて右揃えにして `.num` を付けます。
- **密度：** 大きな表（月次資金繰り表・年月別 収支・入出金予定表）は、表を囲む要素に `data-density="compact"` を付けます。
- **角丸の使い分け：**

| 角丸 | 値 | 使う場所 |
|---|---|---|
| sm | 6px | タグ、Callout |
| md | 8px | ボタン、入力欄、NavItem、タブ |
| lg | 12px | パネル、サイドバー |
| xl | 12px | ダイアログ |

- **追従するもの（FR-56・AC-62）：** **画面の上辺に追従するのは1つだけ**です。
  「見ている口座」と「月の切り替え」を1本のバー（`StickyBar`）にまとめ、
  `sticky top-0` にします。2つ置くと、下の要素の `top` に上の要素の高さを定数で
  書くことになり、折り返す幅でずれます（ADR-0032）。残高ヘッダー（狭い幅のみ）は
  追従しません。**口座の絞り込みと月の切り替えを両方持つ画面は、すべてこれを
  使います** ―― 02 キャッシュフローと 04b 実績一覧。03 年月別収支は月が列なので
  対象外です。バーは1行で、狭い幅では横に送ります。**見ている口座だけは
  `sticky left-0` で左端に残します**（横に送ると隠れるため）。

## 1. 用語（UIで使う言葉）

| 用語 | 意味 |
|---|---|
| 予定 | まだ起きていない入出金。定期項目と単発の予定から生成される |
| 実績 | 実際に起きた入出金。手入力または CSV で登録される |
| 消し込み・照合 | 予定と実績を結びつけること。結びつけると予定は消える |
| 基準日 | 残高を計算し始める日。口座の残高は「基準日時点の残高」として持つ |
| 生活防衛ライン | これより残高が下がると危険とみなすライン（例：¥1,500,000） |
| 区分 | 収入 / 固定費 / 変動費 / 資金移動。CSV取込の画面では「カード引落」も区分として出てくる |
| 資金移動 | 費目グループ TRF。損益に含めない。**口座間振替だけではない** ―― 事業主貸・借入実行・短期資金の受入なども入る。合計残高が変わらないのは、両方の口座が範囲にある振替の場合である |
| カード：確定金額 / 未確定分 | 確定金額は、基準日のあと最初の引き落とし日に計上される。未確定分は、その次の引き落とし日に計上される |
| 事業割合 | 費用のうち事業で使った割合（%） |

- **タブ：** 日次 / 月次
- **グラフ：** 系列はダッシュボードと同じです。凡例は「実績（本日まで）」「予測」「生活防衛ライン ¥1,500,000」です。

#### Panel「月次資金繰り表」（compact）

- **行：** 2026年9月〜2027年2月
- **列：** 入金 / 出金 / 月末残高 / 月中の最低
- **ハイライト：** 月中の最低が生活防衛ラインを下回る月は、行を `highlight`（`bg-warning-subtle`）にします。例は2026年12月です。
- **注記：** 「月末がプラスでも、月中に生活防衛ラインを割る月は色が変わります（2026年12月）。」

#### Panel「口座の日ごとの増減と残高」（compact。FR-64・AC-71）

- **口座を選んでいるときだけ表が出ます。** 合計を見ているあいだは
  「口座を選ぶと…」の案内だけです ―― 出納帳は口座ごとに付けるものなので、
  2口座を足した「日ごとの残高」には突き合わせる相手がいません。
- **列：** 日付 / 増減 / 残高 / 件数
- **先頭に期首残高、末尾に合計の行**を置きます。合計の行は、増減の列に
  増減の合計、残高の列に期末残高が入ります（行の見出しを「期末残高」に
  すると、隣の数字が残高に読めます）。
- **動いた日だけを出します。** 増減が0の日でも、**行が在れば出します**
  ―― 残高に反映しない振替（振替先が未設定・カード）は明細に在るのに
  残高を動かさないので、件数が無いと「この日は何も無い」と読まれます。
- **件数に「予定◯件」を併記します。** 残高は予測系列から取る（AC-49a）
  ので、未記録の予定がある日から先は出納帳と食い違います。
- **表の下に留め具（AC-71）：**
  - 合っているとき：「期首残高 ¥52,000 ＋ 増減の合計 +¥27,000 ＝ 期末残高 ¥79,000。」
  - 合わないとき：`Callout`（error）「増減の合計が残高の動きと ¥7 ずれて
    います。どこかの行を二重に数えているか、落としています。」
  - **合っているときも出します。** 出ないものだけを見ると、正しく黙って
    いるのか、こちらが違う場所を見ているのかを区別できません。
- **上の絞り込み（種別・状態）には従いません。** 絞ると増減の合計が残高の
  動きと合わなくなり、留め具が鳴りっぱなしになります。表の上に1行で
  書いてあります。

#### Panel「入出金予定表」（compact）

- **フィルター（Segmented が3組）：**
  - 期間：先月〜6ヶ月 / 今月 / 3ヶ月 / 6ヶ月 / 12ヶ月 / 期間を指定
  - 区分：すべて / 収入 / 固定費 / 変動費 / カード引落 / 資金移動
    - **1本の軸である**（費目グループと費用区分）。「出金」が無いのはそのため ―― 出ていくものは固定費・変動費・カード引落に分かれる
    - **`すべて` を除く5つは分割。** どの行もちょうど1つに入る（AC-58f）
    - 「入金」ではなく「収入」。資金移動には入る行と出る行が同居していて、**向きは符号で読む**（AC-58b）
  - 種別：予定+実績 / 予定のみ / 実績のみ
- **列：** 日付 / 内容 / 金額 / 残高 / 区分 / 状態 / 備考
- **資金移動の向き（FR-63・AC-70）：** `type = transfer` の行は、**内容の下に
  小さく「移動元 → 移動先」**を出します（例：「現金 → ○○銀行 普通」）。
  **備考には入れません** ―― 備考は1行に1つしか出せず、繰延・未入力が先に
  取るので、向きが落ちます。**合計で見ているとき、閉じる振替には符号が
  付きません**（AC-58b。残高を動かさないので正しい）。向きが出ていないと
  引出しと預け入れの区別が付かず、**逆に入った行を見つけられません**
  （2026-11-12 に 46,000円 ずれた。制約11）。両側記録の行（`type` が
  income / expense で費目が TRF）には出しません ―― 相手が分からず、
  そちらは符号で向きが読めます。**出る行と出ない行が混ざります。**
- **内容を押したときの行き先（FR-41・FR-57）：** 行の種類で違います。
  - **実績の行** → その実績の編集（`Modal`。AC-60）
  - **予定の行** → 元の定期項目・単発予定の**設定**（`/settings#plan-…`。AC-63）。
    飛んだ先では当の行が画面の中央に来て、色が付きます。**明細の中で予定は
    編集しません** ―― させると「この回だけ」と「項目そのもの」のどちらなのかを
    選ばせることになり、明細で見つかる誤り（振替先の未設定・費目の間違い）は
    項目そのものの誤りです（OI-23・ADR-0033）
  - **カード引落の行** → 押せません（CL-2 の生成物で元の設定が無い）
- **備考欄の例：**
  - 振替の行：「合計残高は増減なし」
  - カード引落の行：「自動で作られる行（編集できません）」。編集できないことが分かる見た目にします。
  - 日付をずらした予定：「繰延（元の日付 10/8）」

### 05 CSV取込 `/import` — node `2033:858`

- **PageHeader**
  - タイトル：「CSV取込」
  - サブタイトル：「銀行の明細を取り込みます。取り込むと同時に、予定との照合が自動で行われます」
- **Steps：** 口座を選ぶ › ファイルを選ぶ › 列の割り当てを確かめる › 一括登録

#### Panel「1–2. 口座とファイル」

- **入力欄：**
  - Select「どの口座の明細か」（○○銀行 普通）
  - 「ファイル」（○○銀行_2026-09.csv）と［中身を貼りつける］
- **Callout（caution）：** 「口座を間違えると、別の口座の予定と照合してしまいます。」
- **［デビット明細を選ぶ］（FR-62・AC-69）：** 任意。銀行の明細に
  「デビット　４１２６６９」のように取引ごとの番号しか出ないとき、デビット明細の
  店名に差し替えます。**行は増えません** ―― 両方を取り込むと同じ取引が二重に
  入るので、こちらは摘要の出どころとしてだけ読みます。日付と金額で突き合わせ、
  **±3日のずれ**を許します。**手数料は推測しません** ―― 明細が持っている
  手数料の列（見出しに「手数料」を含む列。事務手数料・ＡＴＭ手数料・
  海外事務手数料）を金額に足して突き合わせ、**金額は完全一致**とします。
  割合の帯は置きません（200,000円の行に1万円ずれた相手が当たるため）。
  当たらなかった行は触りません。**出金の行にだけ当てます。**差し替えた行は摘要列に「明細から差し替え
  （元：…）」を併記します（当たった相手が正しいかを確かめられるように）。
  読んだ件数を出すのは、**0件のファイルを選んだときに気づけるように**するためです。
- **口座は前回選んだものが出ます**（FR-60・AC-67）。いちばん上の口座に戻しません
  ―― 戻ると、気づかずに別の口座へ取り込み、その口座では重複判定の母数が違うので
  「登録済み」が出ません。覚えているのはブラウザで、機械を替えるといちばん上に
  戻ります（ADR-0035）

**仕分けルールの表（06 予定の設定）には［摘要を置き換える］の列があります**
（FR-59・AC-66）。当たる条件ではないので、一意制約（摘要の文字列・口座・向き）
には入りません。**取込時の摘要は残る**ので、置き換えても重複判定は変わらず、
あとから置き換えを変えてもすでに取り込んだ行の判定は変わりません。
**表は横スクロールにしてあります** ―― 列が8つになると `w-full` では列が潰れ、
向きが縦書きになり、置き換える摘要が読めない細い箱になります。

#### Panel「3. 列の割り当て」

- **Select × 4：**

| ラベル | 初期値 |
|---|---|
| 日付の列 | A：お取引日 |
| 摘要の列 | C：お取引内容 |
| 入金の列 | D：お預入額 |
| 出金の列 | E：お引出額 |
| 残高の列 | F：残高（無ければ「（使わない）」） |

**残高の列は見出しからだけ拾います**（FR-61・AC-68）。数として見ると金額の列と
区別が付かず、取り違えると検算が意味のない額を出すためです。見出しの無いCSVでは
「（使わない）」のままになり、検算をしません。

- **Checkbox：** 「金額が1列にまとまっている明細（入金と出金が同じ列）」
- **注記：** 「列は自動で推定していますが、目で確かめてください。Shift_JIS のファイルも読み込めます。」

#### Panel「4. 内容を確かめて一括登録」

- **見出し行の右側：** Primary「12件を登録する」。件数は可変です。
- **列：** 取込 / 日付 / 摘要 / 入金 / 出金 / 照合 / 重複 / 費目 / 決まり方
- **重複列の表示（FR-50・FR-58・AC-65）：** 3つの状態を書き分けます。

| | 条件 | 色 | 取込 |
|---|---|---|---|
| 「登録済み」 | 口座・日付・収支・金額・**取込時の摘要の原文**がすべて一致 | 控えめ | **外してある** |
| 「似た行があります」 | 口座・日付・収支・金額は一致、**摘要が違う** | warning | **入れたまま** |
| （空） | 重なる実績が無い | — | 入れたまま |

  **「登録済み」は控えめな色にします。** 間違いではなく「こちらで外しました」という
  知らせで、利用者がすることはありません。**「似た行があります」は見てほしい** ――
  外していないので、同じ取引なら利用者がチェックを外す必要があります。
  明細の摘要は、保留から確定になるときに変わることがあります。
- **摘要列の差し替え（FR-59・FR-62）：** 摘要が置き換わった行は、その下に
  「明細から差し替え（元：…）」「ルールで差し替え（元：…）」を小さく併記します。
  **見せないと、当たった相手が正しいかを確かめられません。**
  **置き換えが2つぶつかった行**（仕分けルールとデビット明細が違う名前を言う）は、
  **どちらも入れずに**「置き換えの候補が2つあります。どちらも入れていません」と
  出し、［ルール：…］［明細：…］の2つのボタンで利用者が選びます（§2.9）。
- **「次回もこうする」の欄：** ［摘要のどこで当てるか］（初期値は**取込時の摘要の
  原文**。ルールが当てるのは原文なので、差し替わった表示名から作るとどの行にも
  当たらないルールになります）と、［摘要をこれに置き換える（任意）］
  （初期値は**空**。表示名を初期値にすると、置き換えていない行にも置き換えの
  ルールができ、結果が同じなので気づけません）。
- **照合列の表示：**
  - 「自動で照合（9/25 売上入金）」は success 系の色にします。
  - 「要対応（金額が一致しません）」「要対応（候補がありません）」は warning 系の色にします。
- **残高の検算（FR-61・AC-68）：** CSVに残高の列があるとき、表の下に Callout を出します。
  **取込のチェックを変えるたびに出し直します** ―― 外した行のぶんだけ差額が動くので、
  どの行を戻せばよいかが分かります。

| 状態 | tone | 文 |
|---|---|---|
| 一致 | info | 「残高が一致しました（M/D時点で¥X）。取り落としも二重計上もありません。」 |
| 一致しない | error | 「登録される残高が、CSVの残高より¥X 多い／少ないです（…）。取り込めていない行か、同じ行を二重に入れている行があります。」 |
| 鎖が繋がらない | caution | 「残高の列が前の行と繋がっていないので、検算できません。…」 |
| 残高の列が無い | — | **何も出しません** |

  **符号から原因を言いません。** 差が負になるのは「入金の取り落とし」と「出金の
  二重計上」の両方で、決めつけると利用者は無い行を探すことになります。
  同じ文が登録後の知らせにも入ります（確認画面が消えるため）。
- **注記：**
  - 「金額が完全に一致し、日付の差が12日以内で、口座も同じ予定は、その場で消し込まれて「やること」には出ません。」
  - 「CSVのファイル自体はサーバーに保存しません。読み取った結果だけを登録します。」
