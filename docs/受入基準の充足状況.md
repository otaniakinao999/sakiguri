対象：要件定義書 v1.15 の AC-01〜AC-39、および v1.16 以降で追加された AC-40〜AC-44
作成日：2026年9月25日 ／ 最終更新：2026年9月25日

AC-40〜AC-44 はリポジトリの要件定義書（v1.15）にはまだ載っていない。本書では
指示された文面をそのまま条項として扱っている。

AC-38 が「掲げたが一部未実装」だったことを受けて、全件を洗い直した記録。

## 判定の基準

| 列 | 「済」と書ける条件 |
|---|---|
| 実装 | その条項を満たすコードが存在する |
| テスト | その条項を固定する自動テストが存在する。**テスト名に AC 番号があるだけでは足りず、条項そのものを検査していること** |
| 実機 | ブラウザで実際に操作して確認した |

- 3列すべてが埋まらないものは**未**と書く。推測で埋めない
- 複数の条項を持つ AC は条項ごとに判定する
- 実機確認が要らないと判断したものは、理由を備考に書く

## 確認中に見つけたこと

### 「実績」モードが未来月の実績を表示しない（修正済み）

`applyMode`（`src/core/pl.ts`）が `case "actual": return isPast ? actual : null;` になっており、今月より後の月にある実績が「実績」モードで消えていた。

CL-5 手順3（実績側は実績のみを集計する）には期間の限定が無い。過去／未来の切り分けは手順6 の `実績+予定` の定義に属するものであり、それが `実績` に漏れていた。**仕様違反として `return actual;` に修正した。**

未来日の実績は実在する。前払い、CSVの先日付行、そして最も多いのは**日付の打ち間違い**である。2027年と打ってしまった実績が画面から消えると、残高だけが合わない状態になって原因が追えない。

### 表示モードから期間の場合分けをなくした（AC-42・AC-44、修正済み）

4モードそれぞれに、期間の場合分けを持たない定義を与えた（ADR-0020）。`applyMode` は**引数に期間を取らない。**

| モード | 定義 |
|---|---|
| `予定` | 全予定インスタンス（手順2） |
| `実績` | 全実績（手順3） |
| `差異` | **両辺とも発生日が本日以前** |
| `実績+予定` | **本日までの実績 ＋ 未消し込みの予定インスタンス** |

CL-3 との整合を実機で確認した（本日 2026-09-26）。

| | CL-3 入出金予定表 2026年9月 | CL-5 実績+予定 2026年9月 |
|---|---|---|
| 入金 | +535,000 | 収入 535,000 |
| 出金 | −190,000 | 固定費 182,000 ＋ 変動費 8,000 |
| 収支 | 345,000 | 345,000 |

出金の内訳も一致する。実績4件（120,000・25,000・3,000・7,000）に、要対応リストに出ている未消し込みの2件（電気代（変動）5,000・固定資産税30,000）が足されている。

未来日の実績の検知は別の仕組みで扱う（OI-21）。

#### 経緯（同じ誤りを3回通った記録）

| 段階 | 差異の予定側 | 差異の実績側 | 画面に出た誤り |
|---|---|---|---|
| 当初 | 月全体 | 月途中まで | 3費目が予算超過の月が **収支 +14,800（良い方向）**。月初ほど大きく外れるので、毎月1〜2週目が常に黒字に見える |
| ADR-0019 | 本日まで | **月全体** | 未来日の実績125,000 が **−125,000 の予算超過**として出る |

**3回とも「両辺の期間が揃っていない」という同じ形だった。** 1回目と2回目は向きが逆なだけで構造は同じ。片側だけを直すと、誤りの向きが変わって別の症状に見える。

`実績+予定` も同じで、「当月をどちら側に置くか」を決めようとしている限り、月初がほぼ空になるか入力済みの実績が無視されるかのどちらかを選ぶことになる。両方に置く定義（AC-44）にして初めて消えた。
