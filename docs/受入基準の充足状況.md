## 判定の基準

| 列 | 「済」と書ける条件 |
|---|---|
| 実装 | その条項を満たすコードが存在する |
| テスト | その条項を固定する自動テストが存在する。**テスト名に AC 番号があるだけでは足りず、条項そのものを検査していること** |
| 実機 | ブラウザで実際に操作して確認した |

- 3列すべてが埋まらないものは**未**と書く。推測で埋めない
- 複数の条項を持つ AC は条項ごとに判定する
- 実機確認が要らないと判断したものは、理由を備考に書く

## 確認中に見つけたこと

### 「実績」モードが未来月の実績を表示しない（修正済み）

`applyMode`（`src/core/pl.ts`）が `case "actual": return isPast ? actual : null;` になっており、今月より後の月にある実績が「実績」モードで消えていた。

CL-5 手順3（実績側は実績のみを集計する）には期間の限定が無い。過去／未来の切り分けは手順6 の `実績+予定` の定義に属するものであり、それが `実績` に漏れていた。**仕様違反として `return actual;` に修正した。**

未来日の実績は実在する。前払い、CSVの先日付行、そして最も多いのは**日付の打ち間違い**である。2027年と打ってしまった実績が画面から消えると、残高だけが合わない状態になって原因が追えない。

### 「差異」モードは未来月を出さない（判断が要る）

同じ `applyMode` の `case "diff"` に `if (!isPast) return null;` が残っている。実機で 2026年10月に予定100,000と実績125,000を置いた状態でも、差異モードの10月列は `·` のままだった。

手順6 の差異の定義（収入なら `実績 − 予定`、費用なら `予定 − 実績`）にも期間の限定は無い。手順3 と**同じ形の、仕様に書かれていない期間フィルタ**である。

ただし向きは逆で、外すと悪化する。未来月は実績がほぼ0なので、費用の差異が `予定 − 0 = 予定額まるごと` になり、**未来のすべての月で予算を丸ごと節約できたという表示**になる。年計もその分だけ良い方向に膨らむ。

判断が要る。

- **現状（未来月は出さない）を仕様にする**なら、手順6 に「差異は当月以前のみ」と明記する
- **出す**なら、未来月の差異が予定額まるごとになることを受け入れるか、別の定義（例：実績のある月だけ）を決める

### `実績+予定` の当月の扱いが仕様で決まっていない（判断が要る）

手順6 は「過去月は実績、未来月は予定」としか書いておらず、**当月がどちらかを決めていない。** 実装は `月 <= 今月` で判定しているので、当月は実績側になる。

これは観測できる差を生む。今日 2026-09-25 の状態で、9/30 に予定30,000（固定資産税）を置いて `実績+予定` を開いたところ、9月の固定費は**実績の 152,000** になり、まだ到来していない 30,000 は金額として出なかった（予定額の注記「予 159,800」には出る）。

差異モードではさらに効く。同じ状態で9月の差異は次のようになった。

| | 差異（当月に未到来の予定がある） |
|---|---|
| 地代家賃 | −20,000（予定超過） |
| 水道光熱費（固定） | −5,000（予定超過） |
| 消耗品費 | −3,000（予定外） |
| 租税公課 | **+30,000（未到来なだけ）** |
| 収支 | **+14,800（良い方向の色）** |

3費目で予算を超えているのに、**月全体は「良い方向」に見える。** 未到来の予定が節約として計上されるためで、当月を実績側に置く限り必ず起きる。月末が近づくほど正しくなり、月初ほど外れる。

当月をどちら側に置くか、あるいは当月だけ別扱いにするかを決める必要がある。
