# 3,000件の測定手順（AC-34 / AC-28b / AC-28a）

**合成データで取る。** v1.0 の目標値は基準日以降の実績3,000件（§5.1）。10万件は要らない。

貼り付けるものは原本を開いてコピーする（前回と違い、ここには埋め込まない）。

| 使うもの | 場所 |
|---|---|
| 投入・後片付け SQL | `supabase/loadtest/actuals.sql` |
| AC-34 のスニペット | `supabase/loadtest/dupcheck-console.js` |
| AC-28b のスニペット | `supabase/loadtest/timeline-console.js` |

---

## この手順書の使い方

**各手順の末尾に「貼ってください」がある。そこで出力をこの会話に貼る。**

**貼った数値を `docs/受入基準の充足状況.md` に書き込んでから、次の手順に進む。** 書き込みは Claude 側でやる。

> **画面で合否を判断して終わらせないこと。** 判定はその場でできるが、**記録が残らない。** 前回はそれで測定結果が失われた。合否が明らかでも出力を貼る。

全体で2周する。投入は数秒なので安い。

| 周 | `span_days` | 取るもの |
|---|---|---|
| 1周目 | **550**（既定） | AC-34（重複・欠落・逆転）、AC-28b（初回表示） |
| 2周目 | **90** | AC-28a（ページングと到達性） |

**1周目を先にする。AC-34 が「間違う側」の基準だから。**

550日は 3,000件 = 約1.5年という §5.1 の形そのもので、AC-28b の初回表示はその分布で測る意味がある。90日に縮めると月1,000件になり、FR-42 の月内ページング（月200件超で発動）を通せる。**実利用では月約167件なのでこの経路はほとんど通らない。いま取らないと当面どこでも通らない。**

## 手順1 ── 負荷試験用アカウントを作る

**どこで**：アプリ（本番 URL）

`otani.akinao+loadtest1@showtime.design` でサインアップする。

`+` 付きのアドレスは同じ受信箱に届く。新しいメールアドレスは要らない。

> **`+loadtest` を含むことが必要。** 投入・削除の両方にメールアドレスのガードが入っていて、含まないアカウントでは例外で止まる。

**どこで**：Supabase ダッシュボード → SQL Editor

```sql
select id, email from auth.users order by created_at desc limit 5;
```

**この出力をこのまま貼ってください。**（`+loadtest1` の id を使うため）

---

## 手順2 ── ガードが効くことを確かめる

**どこで**：Supabase ダッシュボード → SQL Editor

`supabase/loadtest/actuals.sql` の **投入ブロック**（最初の `do $$ … end $$;`）をコピーし、`load_user_id` に**実データのアカウントの id**（`otani.akinao@showtime.design` のほう）を入れて実行する。

```
ERROR: 負荷試験用アカウントではありません: otani.akinao@showtime.design
```

で止まれば正しい。

> **投入ブロックで試す。削除ブロックでは試さないこと。**
> 投入ブロックは、ガードを抜けても行が増えるだけで消えない。削除ブロックは6テーブルから行を消す。**ガードが効かなかった場合の結果が違う。**

**この出力（エラーメッセージ）をこのまま貼ってください。**

止まらずに実行されてしまった場合は、**そこで止めて報告すること。** 以降の手順に進まない。

## 手順3 ── 3,000件を投入する（1周目）

**どこで**：Supabase ダッシュボード → SQL Editor

`actuals.sql` の投入ブロックを、今度は `load_user_id` に **`+loadtest1` の id** を入れて実行する。`row_total` は既定の `3000`、`span_days` は既定の `550` のまま。

続けて、同じファイルの**確認クエリ**（`-- 確認` の下）を実行する。

**この出力をこのまま貼ってください。**（件数・最も古い日・最も新しい日・カード払いの数）

---

## 手順4 ── AC-34 重複・欠落・並びの逆転

**どこで**：ブラウザのコンソール（`+loadtest1` でサインインした状態）

1. `+loadtest1` のアカウントでアプリを開く
2. `F12`（Mac は `Option+Command+I`）→ **Console**
3. **Chrome の貼り付け保護**：初回は「Allow pasting」を求められる。**コンソールに `allow pasting` と手で打って Enter**（コピペ不可）。一度やればそのタブでは不要
4. `supabase/loadtest/dupcheck-console.js` の全文を貼って Enter

3,000件なら3往復で、数秒で終わる。GET のみ。

**この出力をこのまま貼ってください。**

合格は `重複した id 0` / `欠落 0` / `並びが逆転した箇所 0` の3つだが、**判定せずに全文を貼る。** 往復回数（3のはず）と総件数も記録に要る。

---

## 手順5 ── AC-28b 初回表示

**どこで**：ブラウザのコンソール（同じタブ）

1. ダッシュボードを開く
2. **ハードリロード**：`Shift + F5`（Mac は `Shift + Command + R`）
   - 手順4 が resource timing のバッファを使っているため、読み込み直して空にする
3. 画面の読み込みが終わるまで待つ
4. `supabase/loadtest/timeline-console.js` の全文を貼って Enter

**この出力をこのまま貼ってください。**

見るところは `最後の REST 完了`（§5.1 の3秒以内か）と、小さいテーブル5つが各1回か。`resource エントリ総数` が250未満であることも確認する（3,000件なら余裕で下回る）。

## 手順6 ── 1周目の後片付け

**どこで**：Supabase ダッシュボード → SQL Editor

`actuals.sql` の**後片付けブロック**を、`load_user_id` に `+loadtest1` の id を入れて実行する。

続けて**確認クエリ**（6テーブル＋イベント残を数えるもの）を実行する。

**この出力をこのまま貼ってください。**（`イベント残` 以外がすべて 0 であること）

**アカウントは消さない。** 2周目で使う。

---

## 手順7 ── 90日に縮めて再投入（2周目）

**どこで**：Supabase ダッシュボード → SQL Editor

`actuals.sql` の投入ブロックで、`span_days` を **`90`** に変える。`row_total` は `3000` のまま。

```sql
span_days integer := 90;
```

3,000件 ÷ 3ヶ月 = 月約1,000件になり、FR-42 の月内ページング（200件超）が発動する。

実行して、確認クエリも実行する。

**この出力をこのまま貼ってください。**

---

## 手順8 ── AC-28a ページングと到達性

**どこで**：画面を見る（`+loadtest1` でサインイン）

実績一覧を開く。

| 見るところ | 記録すること |
|---|---|
| 見出しの総件数 | その数字 |
| 月タブ | 何ヶ月分あるか |
| 1つの月を開く | ページングが出るか。1ページの件数 |
| **最後のページまで辿る** | 辿り着けたか。各ページの件数の合計が月の件数と一致するか |
| 同じ行が2ページに出ていないか | 重複の有無 |

**上の表の各行について、見た数字をこのまま貼ってください。** 「問題なし」ではなく数字で。

AC-28a は「見出しに表示した総件数のすべてに、画面上の操作だけで到達できること。重複がないこと」。**到達できたかは、件数を足して一致を見ないと分からない。**

## 手順9 ── 全部片付ける

**どこで**：Supabase ダッシュボード

1. **SQL Editor**：`actuals.sql` の後片付けブロック（`+loadtest1` の id）→ 確認クエリ
2. **Authentication → Users**：`otani.akinao+loadtest1@showtime.design` を削除。`usage_events` は cascade で消える

**確認クエリの出力をこのまま貼ってください。**

> 実データのアカウント（`otani.akinao@showtime.design`）と、検証用の雑収入・固定資産税・ﾄﾞﾝﾎﾟ が入っているアカウントは**消さない。**
