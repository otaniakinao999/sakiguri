# ADR-0033 明細の予定の行から、元の設定へ飛ばす

2026-11-12 ／ FR-57・AC-63・OI-23

## 文脈

入出金予定表で押せるのは**実績の行だけ**だった。予定の行 ―― 振替先が未設定の
定期項目を含む ―― は押せず、明細で見つけても設定の画面まで自分で戻り、
長い表から同じ項目を探し直すことになる。

OI-23 はここで止まっていた。予定を明細から直せるようにすると、**「この回だけ」
と「項目そのもの」のどちらなのかを利用者に選ばせる**ことになる。

## 決めたこと

**明細の中で予定を編集させない。元の設定へ飛ばす。**

- 予定の行の内容が `/settings#plan-recurring-<id>` / `#plan-oneoff-<id>`
  へのリンクになる
- 飛び先の id を作るのは `planAnchorId` **1箇所だけ**（`src/lib/plan-anchor.ts`）。
  リンク側と、表の行に id を付ける側が同じ関数を呼ぶ
- 飛んだ先で、当の行を画面に送り、色を付ける（`usePlanFocus`）
- カード引落（`src: "settle"`）は CL-2 の生成物で元の設定が無いため飛ばさない

## 理由

**出どころの用途では「項目そのもの」が答えである。** 振替先の未設定を明細で
見つけたとき、この回だけ直しても**次回また出る。** 費目の間違いも同じ。
「この回だけ」が要るのは繰延（日付・金額を1回だけ動かす）で、それはやることの
［払えなかった］から入る別の操作である。

**選ばせないほうが短い。** 画面で二択を出すと、どちらが正しいかを利用者が毎回
判断することになる。片方しか正しくない場面でそれを聞くのは、親切ではなく
押し付けである。

## 却下した選択肢

| | なぜ却下したか |
|---|---|
| 明細の中で予定を編集する画面を出す | 上記の二択が出る。加えて、定期項目の編集は「対象月」「発生日」「停止」まで含み、明細の行から想像できる範囲を越える |
| `/settings` に飛ぶだけ（アンカー無し） | **一覧の先頭に戻すだけ。** 明細で見つけた意味が消える。AC-63 がこれを禁じている |
| クエリパラメータ（`/settings?plan=…`）で渡す | 静的生成の前提（ADR-0003）に `Suspense` 境界が要る。ハッシュなら要らない |
| ブラウザのアンカーに任せる | **空振りする。** 飛んだ時点では表がまだ描かれていない（データは Supabase から読み終わってから入る）。`:target` も当たらない ―― 画面内の遷移は履歴の書き換えなので付け直されない。実機で背景が `rgba(0,0,0,0)` のままだった |
| 見つかるまでフレーム数で待つ | 10万件の利用者では読み込みに秒単位かかる。打ち切ると静かに外れる。データが入るたびに呼び直す形にした |

## 影響

- `CashflowLedgerEntry` に `planHref` が増える。`actualId`（実績の編集）と
  **行き先が違う** ―― あちらはその実績、こちらは項目そのもの
- `RecurringTable` / `OneoffsTable` が `focus` を受け取る。`:target` を
  使わないので、どの行かは React の状態で決まる
- **実績が付いた単発予定は既定で隠れている**が、その予定は明細に「予定」の行
  として出ない（実績の行に置き換わっている）ので、そこへは飛べない
- 測り方は `cashflow/__tests__/plan-link.test.ts`。**2つの画面を描いて、
  リンクが指す id が設定の表に実在することを突き合わせる** ―― 片方だけを
  見ると、押しても何も起きないリンクを見逃す。実機でも、押した行の名前と
  飛んだ先の［内容］が一致することと、その行に色が付くことを確かめた
