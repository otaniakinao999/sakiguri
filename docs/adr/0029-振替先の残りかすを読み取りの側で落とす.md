# ADR-0029 振替先の残りかすを、読み取りの側で落とす

- 状態：採用
- 日付：2026-11-11
- 対象：AC-58c / AC-58d、`src/core/types.ts`、`src/core/categories.ts`

## きっかけ

利用者の報告：**入金先が銀行口座のはずなのに、現金で絞り込むとその行が出る。**

振替で入れて振替先に現金を選び、そのあと収支を収入に変えると、振替先の欄は
画面から消えるのに `toAccountId` の値が残る。保存はその値をそのまま書く。

残った値を `touchesAccount` が拾っていた。

| | 非振替の行の `toAccountId` |
|---|---|
| `accountDelta`（残高） | 見ない。**残高は正しかった** |
| `touchesAccount`（一覧の絞り込み・口座削除） | **見ていた** |

**同じ値を読む経路が2つあり、条項（AC-58）は片方しか測っていなかった。**
残高を測って通っていたので、欠陥は本番まで届いた。

## 決めたこと

**2つとも直す。片方では足りない。**

| | どこ | 何をする |
|---|---|---|
| 書き込み（AC-58c） | `fitToType`（core） | 収支が振替でなくなったら `toAccountId` を落とす。**新しく入らない** |
| 読み取り（AC-58d） | `touchesAccount`（core） | 振替のときだけ振替先を見る。**既に入っている行が無害になる** |

```ts
export function touchesAccount(
  item: { type: EntryType; accountId: string; toAccountId?: string },
  accountId: string,
): boolean {
  if (item.accountId === accountId) return true;
  return item.type === "transfer" && item.toAccountId === accountId;
}
```

書き込みの規則は、**予定の設定（`EntryFields`）と実績編集（`ActualForm`）が
同じ1本を呼ぶ形にした。** 元の欠陥は、同じ規則が2箇所にあって片方にしか
書かれていなかったことである（CLAUDE.md §2.8）。そのために `fitCategory` と
`categoryOptionsFor` を `components/ui/inputs.tsx` から `core/categories.ts` に
移した ―― `inputs.tsx` は `"use client"` なので core から引けない（§2.3）。

## 理由

**読み取りの側を直せば、既存データがそのまま直る。** 本番には既にこの形の行が
入っている。マイグレーションも実データの修正も要らない。

**書き込みの側だけでは、既に入っている行が残る。** 新しく入らなくなるだけで、
利用者の画面に出ている行は出たままになる。

**読み取りの側だけでは、値が溜まり続ける。** 表示は正しくなるが、DB には
意味のない `toAccountId` が入り続け、**次に `toAccountId` を読む機能を
足したときに同じ欠陥が再発する。**

## 却下した選択肢

**データを直す（`update actuals set to_account_id = null where type <> 'transfer'`）。**
読み取りの側を直せば同じ結果になるのに、実データに破壊的な操作を走らせる
理由がない（CLAUDE.md §2.5.2）。**消したら戻らない**が、読み取りで落とす分には
いつでも戻せる。

**`accountDelta` のほうを `touchesAccount` に合わせる。** 残高が振替以外でも
振替先を動かすことになる。残高が狂うので論外である。どちらが正しいかは
仕様（AC-58「振替先の口座が動かないこと」）が決めている。

**`toAccountId` を `type = transfer` のときだけ持つ型にする。** 判別可能な
ユニオンにすれば、残りかす自体を型で作れなくできる。`Actual` /
`RecurringItem` / `OneoffItem` の3つと、DB の行、CSV 取込の経路すべてに
波及するので、報告された欠陥に対して大きすぎる。**いまは `fitToType` の
1本で入口を塞いでいる。**

## 影響

- `touchesAccount` の引数に `type` が要る。呼び出しは3箇所（実績一覧の
  絞り込み・年月別収支の絞り込み・口座削除）と、どれも全項目を渡している
- **口座削除（AC-47）の範囲が狭まる。** 非振替の行は、振替先に挙がっている
  だけでは道連れにならない。**これは正しい側である** ―― その行はその口座の
  残高を1円も動かしていない
- ラベル（FR-52・AC-58e）は別件として同じ変更に入れた。収入の行に
  「支払方法」と出ていたのが、報告のきっかけだった
