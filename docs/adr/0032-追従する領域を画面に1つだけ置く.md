# ADR-0032 追従する領域を画面に1つだけ置く

2026-11-12 ／ FR-56・AC-62

## 文脈

利用者の条件はこれだった。

> 今何の口座が見えているのか常に確認できること、且つ月の切り替えがいつでも
> できること。それを満たす追従設定にして欲しい。

いまの状態は条件を満たしていなかった。

| | |
|---|---|
| `BalanceHeader` | `sticky top-0 z-10`。**狭い幅でしか出ない** |
| `PageHeader`（見ている口座がここにあった） | `sticky` 無し |
| `MonthJumpNav`（月の切り替え） | `sticky top-0 z-30`。**狭い幅で残高ヘッダーを覆っていた**（z が上） |

明細の末尾まで送ると、見ている口座が画面から消える。そして追従する要素が
2つ、同じ上辺で重なっていた。

## 決めたこと

**キャッシュフローの上辺に追従するものを1つだけにする。** そのバーに
「見ている口座」と「月の切り替え」を両方入れる。

- `MonthJumpNav` は自分の `sticky top-0 z-30` を捨て、バーの中に入る
- 見ている口座の選択を `PageHeader` の `action` からバーへ移す
- **`BalanceHeader` の `sticky` を外す**
- バーは**1行に収める**。折り返させると高さが変わり、飛び先の
  `scroll-mt-64` が足りなくなって行がバーの下に潜る。狭い幅では横に送る
  （サイドバーのナビと同じ扱い）

重なり順：表の固定セル 10 ＜ **追従バー 20** ＜ 編集の覆い 40 ＜ `AlertDialog` 50。

## 理由

**上辺に2つ置くと、下の要素の `top` に上の要素の高さを定数で書くしかない。**
`BalanceHeader` は `flex-wrap` で折り返すので、高さが幅によって変わる。
375px でずれる。**1つにすれば、重なる余地そのものが無くなる。**

AC-62 が求めているのは「見ている口座」と「月の切り替え」であって、残高では
ない。残高はページの先頭（狭い幅）と `PageHeader`（広い幅）に出ている。

## 却下した選択肢

| | なぜ却下したか |
|---|---|
| 残高ヘッダーを残し、バーの `top` をその高さにする | 高さが定数にならない（上記）。実測で埋めると、文字サイズの設定や口座名の長さで破れる |
| `main` を独立したスクロール領域にして、残高ヘッダーを外に出す | `MonthJumpNav` が `window.scrollY` と `documentElement.scrollHeight` で現在地を決めている。スクロールの主体が変わると、**実測で決めた末尾の扱い**（ADR の無い実測コメントが残っている）が静かに壊れる |
| バーを明細のパネルの中に置く | 明細より上を見ているあいだ、見ている口座が画面から消える。「常に確認できること」を満たさない |
| 残高もバーに入れる | 残高は `computeBalanceSummary`、`PageHeader` は `buildHeaderStats` で、**同じ値を2つの計算から出すことになる**（§2.12） |

## 影響

- **狭い幅で残高の帯が追従しなくなる。** 上まで戻れば見られる。AC-62 の条項
  ではないが、挙動は変わる
- `CashflowViewProps.headerAction` → `accountControl`。描画位置が
  `PageHeader` の右からバーへ変わる
- 月の見出しは、バーが横に送られているとき**選ばれている月が見えないことが
  ある**（自動で寄せていない）。バーを横に送れば出る
- 実績入力・実績一覧には追従バーを置いていない。AC-62 の「明細の末尾まで
  送った位置から」は入出金予定表の条項である。同じ形（口座＋月）なので
  揃えることはできる ―― **仕様の判断なので実装では決めない**
- 測り方は `cashflow/__tests__/sticky-bar.test.ts`。**レイアウトは測れない**
  ので、重なりの原因になる構造（上辺に追従する要素が2つあること）を固定する。
  位置と重なりは実機で見た（広い幅・375px の両方）
