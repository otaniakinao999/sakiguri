# ADR-0047 選んだ帳を、利用者と対で持つ

- 状態: 採用
- 日付: 2026-11-17
- 関連: ADR-0046（共有を grants で表す）、FR-23、FR-31、AC-84

## 文脈

共有が入ると、画面は「**いま誰の帳を読んでいるか**」を持つ必要がある
（`activeOwnerId`）。読み込みはこの値を見て走る。

```ts
useEffect(() => { ... loadAppData(getSupabase(), today, activeOwnerId) ... },
  [userId, today, activeOwnerId, ...]);
```

素直に書くと、選んだ帳は状態1つになる。

```ts
const [activeOwnerId, setActiveOwnerId] = useState<string | null>(null);
```

## 判断

**選んだ帳は、利用者と対で持つ。** 値そのものは状態にせず、対から導く。

```ts
const [chosen, setChosen] =
  useState<{ userId: string; ownerId: string } | null>(null);

const activeOwnerId = userId
  ? chosen?.userId === userId ? chosen.ownerId : userId
  : null;
```

## 理由

**単体で持つと、利用者が変わった瞬間に前の人の帳を1回読む。**

サインアウトして別の人が入ると、`userId` は新しい値に変わる。
`activeOwnerId` は**状態なので変わらない** ―― 前の人が選んでいた帳を
指したままである。React はこの2つを同時には直せない。`userId` の変化を
見て `setActiveOwnerId` を呼ぶ形にしても、**それは次の描画**であり、
そのあいだに上の `useEffect` が走る。

| 順 | `userId` | `activeOwnerId` | 読み込み |
|---|---|---|---|
| 1 | A | A | A の帳 |
| 2 | **B** | **A のまま** | **A の帳 ←これ** |
| 3 | B | B（直した後） | B の帳 |

対で持つと、`chosen.userId !== userId` が一度も成り立たないので
2 の段が存在しない。**直すのではなく、起こらない形にする**
（CLAUDE.md §2.8 の考え方を、規則ではなく状態に当てたもの）。

### 読めはしない。それでも直す理由

2 の読み込みは **RLS に弾かれる。** B が A の帳への付与を持たない限り、
行は返らない。だから**漏れではない。**

それでも直すのは、

- **1回分の往復が無駄に出る。** 10万件を扱う画面で、要らない読みを
  1本増やしている
- **付与を持っている相手なら、実際に A の帳が出る。** 代行者が顧客1から
  顧客2に切り替えたとき、**一瞬だけ顧客1の数字が出る。** これは AC-84
  が防ごうとしている当のもの（どの帳にいるかの取り違え）である
- 既存の検査が**既にこれを捉えていた** ―― 「別の利用者に変わったら
  読み直す」が、2回のはずの読み込みを**3回**と数えて落ちた

## 却下した選択肢

| | なぜ却下したか |
|---|---|
| `activeOwnerId` を単体で持ち、`userId` の変化を `useEffect` で追う | **上の表の2が消えない。** 直すのが「次の描画」なので、要らない読みが1本走る |
| `key={userId}` で Provider ごと作り直す | 効くが、**帳と関係ない状態まで全部捨てる**（`today`・保存の状態・読み込みの試行回数）。効きすぎる |
| `activeOwnerId` を URL に持つ | 画面の数だけ経路が増える。いまは切り替え器を出していない（AC-84 は常時表示）ので、持たせる先が無い |

## 影響

- `activeOwnerId` は**導出値**になった。書き換えるときは `setActiveOwnerId`
  （中で対にして入れる）を使う。直に状態を持たせない
- **一覧に無い帳を指したままにしない。** 付与が失効すると `books` から
  消えるので、消えたら `chosen` を落とす `useEffect` を併せて置いた
- 同じ形を `books` にも使っている（`bookState` が `{ userId, list }`）。
  理由は同じで、**前の人の帳の一覧が一瞬出るのを防ぐ**
