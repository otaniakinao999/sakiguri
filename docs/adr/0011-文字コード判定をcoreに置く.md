# 0011. CSV の文字コード判定を core に置く

## 文脈

CL-7 は文字コード判定を仕様として定めている。

> UTF-8 で厳格デコードを試み、失敗した場合 Shift_JIS でデコードする。先頭の BOM は除去する。

AC-07 も「**Shift_JIS の**銀行CSVを取り込み」と明記している。日本の銀行が出す明細CSVは Shift_JIS が多く、ここが外れると取込そのものが成立しない。

一方 CLAUDE.md §2.3 は `src/core/` に「React / DOM / fetch / `Date.now()` を import しない」と定めている。デコードに使う `TextDecoder` は Web 標準の API であり、この制約に触れるかどうかの判断が要る。

## 判断

`decodeCsv(bytes: Uint8Array | ArrayBuffer): string` を `src/core/csv.ts` に置き、`TextDecoder` を使う。

ファイルを読んでバイト列にするところ（`File` / `FileReader` / `arrayBuffer()`）は UI 層の責務とし、core はバイト列だけを受け取る。

## 理由

**`TextDecoder` は DOM ではない。** `window` にも `document` にも依存せず、ブラウザと Node の双方でグローバルとして利用できる。同じバイト列からは必ず同じ文字列が返る純関数であり、CLAUDE.md §2.3 が core に求める「入力を渡すと同じ出力が返る」を満たす。禁止列挙にある React / DOM / fetch / `Date.now()` は、いずれも「外界の状態に触れる」ことが問題なのであって、`TextDecoder` はそれに当たらない。

**仕様として書かれたロジックを、テストの効かない場所に置きたくない。** UI 層に出すと、UTF-8 の厳格デコードが失敗したときのフォールバックも、BOM の除去も、AC-07 のテストから外れる。PoC開発計画 §5.1 が最大の懸念に挙げているのは「計算ロジックの静かな回帰」であり、文字コードの判定はまさに静かに壊れる種類のコードである。文字化けは例外を出さない。

**Node で検証できる。** Node 24 は full ICU を同梱しており、`new TextDecoder('shift_jis')` が動く。UTF-8 の厳格デコードが Shift_JIS のバイト列で `TypeError` を投げることも確認した。Vitest の node 環境でそのままテストできる。

## 却下した選択肢

**core は復号済みの文字列だけを受け取り、判定は UI が行う。** 制約の字面には最も安全。ただし AC-07 の中心にある「Shift_JIS を読めること」がテストされないまま残る。judgement としては、境界の純粋さより受入基準の検証可能性を採った。

**`encoding-japanese` などのライブラリを使う。** 判定精度は上がるが、CLAUDE.md §2.7 の許可リストにない依存が増える。標準 API で仕様どおりの動作が得られる以上、増やす理由がない。

**バイト列を見て自前で判定する。** UTF-8 の妥当性検査を自分で書くことになる。`TextDecoder` の `fatal: true` がまさにその判定であり、書き直す意味がない。

## 影響

- `src/core/csv.ts` は `TextDecoder` を参照する。core が触れてよい外部 API はこれが最初の例になる。**同じ理屈で `fetch` や `localStorage` を持ち込まないこと。** それらは外界の状態に触れるため、`TextDecoder` とは性質が違う
- `TextDecoder` が使えない実行環境では動かない。要件定義書 §5.5 の対応ブラウザ（Chrome / Safari / Edge の最新2バージョン）はいずれも対応している
- Shift_JIS のデコードは実行環境の ICU に依存する。Node で full ICU が無い構成ではテストが落ちる。開発環境の前提として README に Node 20 以上を書いてある
- **エンコードはできない。** Node に Shift_JIS のエンコーダは無いため、テストで Shift_JIS のバイト列を作るときは必要な文字だけを表引きしている。会計ソフト向けの CSV 出力（FR-22、v2.0）で Shift_JIS 出力が要るなら、そこで改めて判断する
