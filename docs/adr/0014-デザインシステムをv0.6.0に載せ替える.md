# ADR-0014 デザインシステムを「Design System sakiguri v0.6.0」に載せ替える

## 文脈

v1.0 までの UI は `docs/designsystem.md`（Vastra Design System の写し）を一次情報とし、
`src/styles/tokens.css` がその逐語転記、`src/app/globals.css` が Tailwind への橋渡しという形だった。

2026年10月、Figma で `Design System sakiguri`（fileKey `diqeunxgHCLNIPKVXL4evB`）v0.6.0 が確定し、
`docs/design/` 一式（`tokens.css` / `components.md` / `screens.md` / `decisions.md`）が渡された。
これは Vastra の派生ではなく、sakiguri 専用に作り直されたものである。

主な差は3つ。

| | v1.0（Vastra） | v0.6.0（sakiguri） |
|---|---|---|
| ブランド | blue `#065D63` | **teal** `#065d63`（同値。名前が変わった） |
| エラー | purple | **plum** |
| 注意 | green | green（変わらず） |
| トークン名 | `--object-base-high` / `--surface-base-primary` | `--foreground` / `--background`（shadcn 互換） |
| 部品 | 自前 | **shadcn/ui をベースに、sakiguri 固有はラップ部品** |

## 判断

1. **トークンの一次情報を `docs/design/tokens.css` に移す。**
   `src/styles/tokens.css`（旧）は移行が終わるまで残し、最後に消す。
2. **新旧のセマンティック名を一時的に併存させる。**
   画面を1枚ずつ移し、移し終わった画面から旧名を外す。各段階でビルドが通る状態を保つ。
3. **shadcn/ui・Radix・cva・Heroicons を許可済み依存に加える**（CLAUDE.md §2.7）。
   `docs/design/HANDOFF_CLAUDE.md` がこれらを名指しで要求している。
4. **余白は px 名のスケールを維持する**（`p-16` ＝ 16px）。
   Tailwind 既定（`p-16` ＝ 64px）には戻さない。
5. **フォントは @fontsource で自己ホストする。**

## 理由

**4 がこの ADR の肝である。** v0.6.0 の余白は 2/4/6/8/12/16/20/24/32/40/48/64/80px で、
すべて4の倍数である。したがって既存の px 名スケールに不足分（2・6・20・80）を足すだけで表現でき、
**ADR-0004（既定スケールを殺し、スケール外を書くとクラスが生成されないことで気づける）を緩めずに済む。**

`components.md` / `screens.md` は Tailwind 既定の名前（`p-6`、`gap-6`、`px-8`）で書かれているが、
これは 4倍して読み替える（`p-6` → `p-24`）。読み替えは一意で、曖昧さがない。

既定スケールに戻す案も検討したが、既存29コンポーネント・約6,200行の `p-16` がすべて
64px に化ける。**規約で守るのではなくビルドで落とす**という ADR-0004 の利点を、
移行の都合で手放す理由がない。

5 について。この開発環境からは `fonts.googleapis.com` に到達できず、`next/font/google` が動かない。
加えて v0.6.0 は和文の本文書体に **Noto Sans JP** を指定しており、ADR-0005 が
「日本語サブセットが数MBあるため Web フォントとして読み込まない」とした判断に正面から当たる。
@fontsource は unicode-range で約100分割して配信するため、実際に使う字だけが落ちてくる。
**ADR-0005 の懸念（数MBの一括ダウンロード）は、この配信形式では起きない。**
非機能要件 5.1（初回表示3秒以内）に対する影響は、移行後に実機で測り直す。

## 却下した選択肢

- **別リポジトリで作り直す。** `src/core/` の業務ロジックと740本のテスト、
  受入基準の充足記録を捨てることになる。デザインの変更は表示層の話であり、計算は変わらない。
- **トークンだけ差し替えて一括で直す。** 29コンポーネントが同時に壊れ、
  どこまで直したかが分からなくなる。1画面ずつ移せる形を選ぶ。
- **`docs/designsystem.md` を書き換えて一次情報の場所を変えない。**
  Figma が一次情報であり、`docs/design/tokens.css` はその書き出しである。
  間に写しを挟むと §2.8（同じ規則を2箇所に書かない）に反する。

## 影響

- `CLAUDE.md` §2.6（トークンの置き場所）と §2.7（許可済み依存）の本文が古くなる。
  移行完了時に書き換える。
- `docs/designsystem.md` は v1.0 の記録として残すが、一次情報ではなくなる。
- 色の意味が変わるため、**スクリーンショットを使った過去の記録は読み替えが要る。**
- 移行中は新旧のトークンが両方生きており、`src/styles/tokens.css` を消すまでは
  CSS 変数が二重に定義される。

## 追記：v0.6.0 に無いものの扱い（ダッシュボード、2026-10-19）

画面を実データに繋ぐ段で、**v0.6.0 の Figma に無いものが v1.0 に7つ
あった。** Figma を正として作ると、いずれも要件か受入基準に反する。
**残した。**

| 残したもの | 根拠 |
| --- | --- |
| 残高警告の3文面と2つの導線 | 指標「残高警告からの操作率」の分子（`shortfall_acted`） |
| 警告を見せた記録 | 同じ指標の分母（`shortfall_warned`） |
| 消し込みの警告2種 | FR-43。うち「まだ一度も消し込みが行われていません」は AC-29c |
| 現預金 合計 | 口座が複数あるとき、合計が無いと足し算を利用者にさせる |
| カードの次回引落 | 口座残高だけ見て足りると思った翌週に引落が来るのを防ぐ |
| 借入の注記 | 要件定義書 §7 制約3「利用者にはその旨を画面上で注記する」 |
| 未登録・読み込み中の状態 | Figma は値のある状態しか描いていない |

**作り方。** `DashboardView` に差し込み口（`heroNotice` / `notices` /
`total` / `footer` ほか）を開け、文言は `DashboardNotices.tsx` に
一本化した。Figma にある部分の見た目は変えていない。

逆に **Figma にあって本番に出していないものが1つ**ある。やること各行の
「予定どおり」。この画面に消し込みの処理が無く、押しても何も起きない
ボタンになるため。実績入力の画面を v0.6.0 に載せ替えるときに戻す。
Figma と見比べる `/dev/screens/dashboard` には出してある。

### 期間タブを実際に動かした

Figma の 90日／6ヶ月／12ヶ月（2029:103）は絵だけだったが、予測系列は
基準日から24ヶ月ぶんあるので、そのまま横幅を変えられる。

**最低残高と警告は連動させない。** 要件定義書 §4.1 SC-02 が見るのは
90日で、連動させると「12ヶ月」を選んだ瞬間に警告の意味が変わる。
タブはグラフの横幅だけを変える。`dashboard-view-model.test.ts`
「期間を広げると点が増える。最低残高と警告は変わらない」で固定した。

### 画面の中に計算を置かない

この画面は Supabase に繋がないと開けない。props を作るところを画面に
置くと、**確かめる手段が目視しか無くなる**（そして見ていない場所は
「合っている」側に倒れる。要件定義書 §9.1 の6つ目）。
`dashboard-view-model.ts` を純関数にして、`dashboard-fixture.ts` から
本番と同じ経路を通す検査と、確認用のページ
`/dev/screens/dashboard-wired` を置いた。**残りの画面も同じ形にする。**

## 追記：確定した2件（2026-10-19）

### 収入と固定費のタグは同じ背景色のままにする

`--primary-subtle`（= `--brand-50` → `--teal-50`）と `--success-subtle`
（= `--teal-50`）が同値のため、**収入（success）と固定費（info）の
タグは背景が同一の #edf6f6 になる。** 文字色だけが #1a7a80 と #065d63
で違う。変動費の #f0fdf4 もこれに近い。

**これで進める（利用者の判断、2026-10-19）。** ブランド色をティールに
割り当てている以上の衝突であり、直すには収入か固定費のどちらかを
ブランド色から外すことになる。**色を直す提案を繰り返さない。**
区別が要るという話が出たら、背景ではなく枠線か文字の濃さで分ける。

### フォントは @fontsource のままにする

HANDOFF_CLAUDE.md は `next/font/google` を指定しているが、
`fonts.googleapis.com` / `fonts.gstatic.com` に到達できない環境が
あるため @fontsource（Google Fonts の npm 配布。woff2 と @font-face を
`node_modules` から読む）に差し替えてあった。

**このまま使う（利用者の判断、2026-10-19）。** 第三者へのリクエストが
無くなり、オフラインでビルドできる。和文も unicode-range で分割されて
いるので、実際に使う字だけが落ちてくる。戻し方は
`src/app/layout.tsx` の冒頭コメントに残してある。

非機能要件 5.1（初回表示3秒）は、この構成で実環境で測り直す。

## 追記：年月別 収支（03、2026-10-19）

### Figma に無いが残したもの

### 「収支」を「差引」に変えた

`buildPLDisplay` の `netLabel` は「収支」で、テストが固定していた。
v0.6.0 の Figma 2031:256 と screens.md 03 の行の表はどちらも「差引」で、
Figma の注記も「差引は 収入 − 固定費 − 変動費 です」と書いている。
**デザイン側2つが一致しているので差引を採り、テストも直した。**
画面の名前（年月別 収支）は変えていない。戻すなら pl-view.ts の1行。

事業スコープの「事業所得」はそのまま。税の用語なので変えない。

### 金額に符号も色も付けない

Figma の費用は ¥106,400 のように実額で並び、注記も「費用は実額で」と
書いている。**ほかの画面の `Amount` をそのまま持ち込むと「−」が付く。**
この画面は `formatAmount` を直接使う。小計・合計だけ `text-fg-primary`
にする（Figma の数字がティール）。差異モードだけは符号と色を出す。

### 当初予算の間引きを純関数に移した

`buildPLDisplay` は当初予算を生のまま返す。「見込みと違う月にだけ出す」
という仕様の判定は**旧 ProfitLossMatrix の描画の中にあり、純関数からは
見えなかった。** そのまま描いたら「¥0 予¥0」が12ヶ月ぶん並んだ。
`pl-view-model.ts` の `keepPlan` に移し、テストで固定した。

### screens.md と Figma の食い違い

- 「実績+予定」の説明は screens.md が Callout（info）と書いているが、
  Figma は枠も背景も無いただの注記。**Figma を採った。**
- Figma には注記が2つある（screens.md は1つ）。2つとも出す。
- 費目列は 176px で折り返させない。既定のままだと「税金（所得税・住民税）」
  が7行に割れた。

## 追記：CSV取込（05、2026-10-19）

### 照合できなかった理由を core に足した

Figma 2033:1000 の「照合」列は「要対応（金額が一致しません）」と
「要対応（候補がありません）」を書き分けている。`ImportRow` はこの区別を
持っていなかった。

**画面側で判定しない。** 照合は `planMatches` が唯一の定義で
（CLAUDE.md §2.8）、条件を画面に写すと片方にだけ条件が増える。実際
AC-33 の「口座が一致」は `matchPlan` と `isCandidate` の両方に手で
足されていた。同じことを繰り返さないために、

- `planMatchesExceptAmount` を `planMatches` の**隣**に切り出し、
  `planMatches` 自身がそれを呼ぶようにした。金額以外の条件は1箇所のまま。
- `ImportRow.matchHint`（`matched` / `amountDiffers` / `noCandidate`）を
  `buildImportRows` が付ける。照合しているその場で決まる。

利用者が次にすることが変わるので、文面を分ける価値がある（金額を直すのか、
予定を作るのか）。

### Figma に無いが残したもの

| 残したもの | 根拠 |
| --- | --- |
| 取込の可否（行ごとのチェック） | 要らない行を外せないと取り込みをやり直すしかない |
| 「読み取る」ボタン | 列の割り当てを直してから読み直せるようにする |
| カードを選んだときの注記 | 利用日で取り込んで引落日に寄せる挙動がここにしか無い |
| エラー・完了の知らせ | ファイルの上限・行数超過・登録件数 |
| `csv_imported` / `actual_recorded` の記録 | FR-43・指標 |

### 部品を4つ足した

Steps（2009:80）、Input、Select、Checkbox。06 でも使う。
**Select はネイティブの `<select>` にした。** 候補が多いとき
（費目・口座・月）に自前の仮想スクロールが要るうえ、モバイルの既定の
選択 UI を捨てることになるため。見た目だけ寄せている。
その結果 `@radix-ui/react-select` が未使用になった。外すか使うかは別途。
