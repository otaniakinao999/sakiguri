# 0005. Web フォントは Inter と Cormorant Garamond のみ読み込む

## 文脈

`docs/designsystem.md` §2.1 は3つのファミリを定義する。

| トークン | 先頭ファミリ | 用途 |
|---|---|---|
| `--family-ui` | Inter | 本文・ラベル・ボタン・数値。アプリ画面のほぼすべて |
| `--family-display-en` | Cormorant Garamond | ワードマーク「SAKIGURI」のみ |
| `--family-display-jp` | Noto Serif JP | カード見出しなど和文の見出し |

プロトタイプは3つとも Google Fonts の `@import` で読み込んでいる。

要件定義書 5.1 は初回表示3秒以内（4G 想定）を求める。Noto Serif JP の日本語サブセットは数MBある。

## 判断

- Inter と Cormorant Garamond を `next/font/google` で読み込み、生成されたファミリ名を `--font-inter` / `--font-cormorant` として `tokens.css` が受け取る
- **Noto Serif JP は Web フォントとして読み込まない。** 端末にある場合のみ効かせる
- CSS の `@import url(fonts.googleapis.com/...)` は使わない

## 理由

`@import` はレンダリングブロックになり、初回表示の予算を直接削る。`next/font` はビルド時にフォントを自己ホストし、外部への追加接続を消す。

実行時に fonts.googleapis.com へリクエストが飛ばないことにも意味がある。PoC開発計画 §4 は「外部の解析ツールを入れない。資金繰りの金額が第三者に渡る経路を作らないため」としている。フォント配信も同じ経路になりうる。

Noto Serif JP を外すのは費用対効果の問題である。用途はカード見出しに限られる一方、コストは数MBで、3秒予算のほぼ全部を食う。`--family-display-jp` のフォールバックは Hiragino Mincho ProN / Yu Mincho で、macOS と Windows の大半を覆う。要件定義書 5.5 の対応ブラウザ（Chrome / Safari / Edge）はこの2つのOSに乗る。

## 却下した選択肢

**3ファミリすべてを next/font で読む。** 初回表示3秒（4G）に対して Noto Serif JP が重すぎる。見出しの字形のために本文の表示を遅らせることになる。

**プロトタイプどおり `@import` で読む。** レンダリングブロックであり、かつ実行時に第三者へ接続する。プロトタイプは単一ファイルで動かすための実装であり、そのまま持ち込む前提のコードではない（PoC開発計画 §3、§5.10）。

**Noto Serif JP をサブセット化して自己ホストする。** 効果はあるが、和文の字種は利用者の入力（費目名・取引先名・摘要）に依存するため、静的サブセットでは足りない。動的サブセットは配信基盤が要る。PoC の範囲を超える。

## 影響

**Noto Serif JP を持たない端末では、和文見出しが Hiragino Mincho / Yu Mincho / 総称 serif になる。** 「明朝の見出し」というデザイン意図は保たれるが、字形は端末によって変わる。

`tokens.css` の `--family-ui` と `--family-display-en` は、designsystem.md の記述に `var(--font-*)` を1段かぶせた形になっている。

```css
--family-ui: var(--font-inter, "Inter"), "Hiragino Kaku Gothic ProN", ...;
```

第2引数に原典のファミリ名を残してあるため、next/font が無い環境（テスト、Storybook など）でも壊れない。**これは tokens.css が designsystem.md の逐語転記から外れる唯一の箇所である。**

Inter は和文の字形を持たない。日本語は `--family-ui` の第2ファミリ以降（Hiragino Kaku Gothic ProN / Yu Gothic / Meiryo）に落ちる。これは designsystem.md が意図した構成であり、欠陥ではない。
