# ADR-0042 確認画面の行ごとの編集を、手で直した印1つで揃える

日付：2026-11-13
関連：CL-7（要件定義書 §3.3）・AC-45・AC-57a・AC-57b、CLAUDE.md §2.8・§2.9

## 文脈

CL-7 の確認画面の条項はこう書いている。

> 取込前に全行を一覧表示し、行ごとに **取込可否・収支・固定変動・費目・事業割合**
> を修正できること。自動照合された行は照合先を明示すること。

**画面にあったのは取込可否と費目の2つだけだった。** 費目の列は FR-18
（仕分けルール）の作業中に足したもので、それまでは費目も直せなかった。
`docs/受入基準の充足状況.md` は「残り2つは未実装」と書いていたが、**5つの
うち2つが在るなら足りないのは3つ**である。その行が間違っていた。

**急ぐ理由は事業割合である。** §3.3 が同じことを書いている ――
「事業割合が 100 から 0 に変わると、事業と家計の間で金額が移動する」
「合計は合うため、内訳を見ないと気づけない」。取込のあとに1行ずつ直すと、
記帳代行の手数にそのまま乗る。

## 判断

### 1. 固定変動と事業割合の列を足す

| | 出す行 | 出さない行 |
|---|---|---|
| 固定変動 | 費用 | 収入・資金移動（適用規則6） |
| 事業割合 | 資金移動以外 | 資金移動 |

**出す／出さないの条件は core の `costTypeApplies` / `groupOfCategory` から
引く。** 画面の条件を別に書くと、画面から入らない値が core には入る（§2.8）。
**core 側でも落とす** ―― `editImportRowCostType` は費目が固定変動を持たない
行では行をそのまま返す。

### 2. 3つの編集が「手で直した印」を共有する

`handEdited` を1つ置き、費目・固定変動・事業割合のどれを直しても
`ruleId` / `rulePattern` / `guessedFrom` を外す。

**「手で直した」という印を別に持たせない**（既存の判断。`ruleId` が印を
兼ねる）。片方の編集だけ印を外すと、**事業割合だけ手で直した行が
［このルールを使わない］の決め直しで巻き戻る**（AC-57b）。

### 3. 初期値の決め方には触らない

照合が成立した行は費目・固定変動・事業割合を**照合先の予定から引き継ぐ**
（AC-45、v1.17）。この変更は「直せるようにする」だけである。

### 4. 表は内容ぶんの幅を取る

11列を `w-full` で収めると、固定変動の `<select>` が 30px まで潰れ、照合の
文が縦に折り返す（実機で確認）。設定の表・年月別収支と同じく `w-max` にして、
パネルの `overflow-x-auto` で横に送る。

## 却下した選択肢

### 収支（入金／出金）も同じやり方で直せるようにする

**退けた。行の中だけで閉じないためである。**

収支を変えると、少なくとも4つが変わる。

| | なぜ |
|---|---|
| 照合 | `matchPlan` が向きを見る。**予定は1行にしか取られない**（`claimed`）ので、1行だけ決め直すと取り合いの結果が変わる |
| 重複 | `markDuplicates` は**2段階**で、原文まで一致した行に先に枠を使わせる。1行だけ決め直せない |
| ルール | `ruleMatches` が向きで絞る。当たるルールが変わり、**摘要の置き換え**（FR-59）も変わる |
| 費目 | 受け皿が収入と費用で別（適用規則4） |

**半端に足すのがいちばん危ない。** 向きを変えても `matchedKey` が残れば、
**向きの違う予定を消し込んだ実績が黙って入る**（`actualFromImportRow` が
`key` をそのまま書く）。合計では見えない。

直すなら、**行ごとの手直しを「上書き」として別に持ち、`buildImportRows` を
上書き付きで流し直す**形になる。いまは確認画面の行そのものが状態なので、
流し直すと利用者の手直しが消える（既存のコメントがその理由を書いている）。
**状態の持ち方を変える作業なので、この変更には混ぜない。**

## 影響

- **手で直したことが「決まり方」の列に出ない行がある。** 照合が成立した行は
  `matchedKey` があるので「予定から」のままになる。印を増やすと §2.8 の
  重複になるので、**値そのものが欄に出ていることで足りる**とした。
- 確認画面の `<select>` に行の名前（`${row.name} の費目` など）を付けた。
  表の中では `<label>` を置けないので、読み上げが「費目」としか言わず、
  行が何十も並ぶ画面ではどの行か分からなかった。
- 収支が直せないあいだの逃げ道は、**列の割り当てを直して読み直す**こと
  （入金・出金の列、または1列の符号）。1行だけ向きが違う明細には効かない。
