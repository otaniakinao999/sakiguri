# ADR-0035 取込先の口座をブラウザに覚えさせる

日付：2026-11-12 ／ 対応：FR-60・AC-67 ／ 関連：AC-64

## 文脈

取込の口座は画面の状態でしか持っていなかった。

```ts
const activeAccount = accountId || data.accounts[0]?.id || "";
```

**画面を開くたびにいちばん上の口座に戻る。** 気づかずに別の口座へ取り込むと、
その口座では重複判定の母数が違うので「登録済み」が出ない（`countByKey` は
口座で厳しく絞る）。利用者の「登録済みの数が毎回変わる」の一因である。

## 判断

**ブラウザの `localStorage` に、利用者ごとの鍵で覚える。**

`settings` の列にはしない。

## 理由

**取り込むファイルはその機械にある。** 覚えるべき値は「この機械で前回選んだ
口座」である。`settings` にすると機械をまたいで揃うが、片方の機械で選び直すと
もう片方が変わる。取込は機械ごとの操作なので合わない。マイグレーションも
要らない。

**利用者ごとに鍵を分ける。** 1つの鍵にすると、同じブラウザで別の利用者が
サインインしたときに**前の利用者の口座 id がその画面に残る。** 選べはしない
（その id は相手の口座一覧に無い）が、他人のデータの断片を持たせない。

**効果で後から直さない。** 最初の描画でいちばん上の口座を出してから効果で
入れ替えると、その一瞬のあいだに［読み取る］を押せてしまう。描画のたびに
純関数 `pickImportAccount` が決める。

**覚えた口座が「いま在る口座か」を確かめる。** 覚えたあとで口座を消していると、
存在しない id が `<select>` の値になり、**どの選択肢も選ばれていない見た目**に
なる。そのまま読み取ると、どこにも属さない実績ができる。

**読めなくても壊れない。** プライベートウィンドウやサイトデータを止めている
環境では例外が飛ぶか空が返る。そのときは「覚えていない」と同じ扱いにする。

## 却下した選択肢

**`settings` に列を足す。** マイグレーションが要り、機械をまたいで揃うことが
この用途では害になる（上）。

**URLに持たせる。** 静的生成の前提（ADR-0003）にクエリパラメータを足すと
Suspense 境界が要る。口座の選択はそこまでの重みがない。

## 影響

- `localStorage` の鍵が1つ増える（`sakiguri:import-account:<userId>`）
- 機械を替えると覚えていない。いちばん上の口座で開く（仕様どおり）

## 測ったこと

`components/import/__tests__/import-account.test.ts`（12件）。

**覚えさせるのは「いちばん上ではない口座」**（3番目の `a2`）。先頭を覚え
させると、`accounts[0]` を返すだけの実装 ―― 直す前の実装 ―― でも通る
（CLAUDE.md §2.11）。**覚えていないときはいちばん上に戻ることも同じ実行で
測る。** 純関数だけでなく画面の `<select>` の値も見る（§2.7 末尾）。

壊して測った6通りで1〜4件が割れる。

| 壊し方 | 落ちた |
|---|---|
| いつもいちばん上の口座 | 4 |
| 消えた口座を確かめない | 2 |
| 画面で選び直したほうを見ない | 1 |
| 利用者ごとに鍵を分けない | 2 |
| 選び直しても覚えない | 1 |
| 画面が覚える関数を呼ばない | 1 |

実機（本番DB・負荷試験アカウント、口座3件）で、2番目の口座を選んで開き直すと
その口座のままであることを確認した（既定はいちばん上）。
