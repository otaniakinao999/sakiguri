# 0022 基準日の変更は止めずに確認を挟む

## 文脈

マニュアルの文言を実機と突き合わせる作業で見つかった。

**仕様（OI-6）もマニュアル2本も「基準日は後から変更できない」前提で書かれていたが、実装に制限は一切なかった。**

```tsx
<DateInput value={data.asOf}
  onChange={(e) => setData((d) => setAsOf(d, e.target.value))} />
```

`setAsOf` は `{ ...data, asOf }` を返すだけで、確認も警告もない。**「予定の設定」を開けば誰でも変えられる。**

基準日が変わると何が起きるか。

- **その日付より前の実績が、残高の計算から外れる**（CL-3 の開始残高が基準日時点で定義されている。FR-47 も基準日以降しか読まない）
- **口座の残高の意味が変わる。** 入力してある金額は「基準日時点の残高」なので、基準日が動くと同じ数字が別のものを指す
- 数字は大きく動くが、**原因が画面から分からない**
- 元の日付に戻せば復帰するが、**何日だったかを覚えていないと戻せない。変更後の画面にはどこにも残らない**

PoC の問い（予測が実感と合うか）を確かめている最中に、税理士が見る数字がこれで狂うと、**問いそのものが汚染される。**

## 判断

**変更を禁じない。変更の前に確認を1つ挟む。**

確認の文面には3つを入れる。

1. この日付より前の実績が残高計算から外れること
2. 口座の残高が「新しい基準日時点の残高」として読み直されること
3. **変更前の日付**

**3つ目が要点である。** 1と2は「変えてはいけない」と伝えるだけだが、3は**間違えたあとに戻す手段**になる。変更後の画面に元の日付は残らないので、ここに出さないと復旧できない。

「この日付は変更後の画面に残りません。必要なら控えてから進めてください」も添える。

## 理由

**禁じなかったのは、OI-6 が未決だからである。**

OI-6 は「基準日を後ろにずらす操作を許すか。ずらすと過去の実績が残高計算から外れるため、締め処理として設計する必要がある」で、v1.5 の検討事項として残っている。**許す可能性が残っているものを、仕組みで禁じると後で外すことになる。** 外す作業は、入れる作業より見落としやすい。

いま困るのは「変えられること」ではなく「**気づかないまま変わること**」である。確認はそこだけを塞ぐ。

**運用ルール（マニュアルに「変えないでください」と書く）だけにしなかった理由。** スタッフは「予定の設定」を見ないことになっているが、見られる状態にはある。マニュアルを読んでいない人、読んだが忘れた人、別の項目を直すついでに触った人は止まらない。**確認は、読んでいない人にも届く。**

## 却下した選択肢

**入力欄を読み取り専用にする。** 却下。OI-6 が許す方向に決まったときに外す必要があり、そのとき「なぜ読み取り専用なのか」の理由が残っていないと、安全のためだと誤解して残る。また、初期設定のやり直し（基準日を打ち間違えた直後）ができなくなる。

**変更後に「元に戻す」ボタンを出す。** 却下。戻す操作を1つ足すと、戻す対象が何かを画面が覚えることになる。状態が増える。**変更前に日付を見せれば、戻すのは既存の入力欄で足りる。**

**マニュアルだけで運用する。** 却下。上のとおり、読んでいない人に届かない。

## 影響

- `src/components/settings/SettingsScreen.tsx` — `pendingAsOf` を持ち、確認してから `setAsOf` を呼ぶ
- `src/lib/format.ts` — `formatYearMonthDay`。`formatMonthDay`（9/14）は年が落ちるので、**戻すための控えには使えない**
- 仕様側：OI-6 の記述と、マニュアル2本の「後から変更できません」は、**実装と食い違っていた。** マニュアルは「変更できてしまいますが、変えないでください」に直した（仕様の書き手が対応）
