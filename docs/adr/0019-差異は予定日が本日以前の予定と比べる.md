# 0019. 差異は予定日が本日以前の予定と比べ、期間の場合分けを置かない

## 文脈

CL-5 手順6 の差異モードには、仕様に書かれていない期間の分岐が2つ入っていた。

```ts
case "diff":
  if (!isPast) return null;                                   // ①
  return group === "income" ? actual - plan : plan - actual;
```

```ts
const isPast = months.map((m) => m <= currentYearMonth);      // ②
```

① は未来月を隠す。② は**当月を過去として扱う**ため、当月にまだ到来していない予定が予定側に丸ごと残る。

② の影響が大きい。本日 2026-09-25、9/30 に固定資産税30,000の予定がある状態で、実際には3費目が予算超過している月が次のように出た。

| 行 | 差異 |
|---|---|
| 地代家賃 | −20,000（予定超過） |
| 水道光熱費（固定） | −5,000（予定超過） |
| 消耗品費 | −3,000（予定外） |
| 租税公課（未到来） | **+30,000** |
| 収支 | **+14,800（良い方向の色）** |

**この機能が伝えるべきことの逆を伝えている。** しかも未到来の予定は月初ほど多いので、**毎月1〜2週目は常に「うまくいっている」と表示される。** 計算は合っており、合計も整合し、例外も出ないため気づけない。

① と ② はどちらも「差異は実績が出揃っていない期間では意味を持たない」という同じ事実への場当たりの対処である。

## 判断

規則を1つ置き、①と②の分岐を**両方削除する。**

> **差異は、予定日が本日以前の予定インスタンスと実績を比べる。**

集計日は発生日（カードは利用日。手順4）なので、判定も発生日で行う。

実装は `PLMatrix` に3面目 `planToDate` を持つ。予定側と同じ手順で、`event.date <= today` の予定インスタンスだけを集計する。行の並びは予定側と揃え、落ちた費目も0の行として残す。`applyMode` の差異は `planToDate` と実績を比べるだけになり、期間の引数を見ない。

```ts
case "diff":
  return group === "income" ? actual - planToDate : planToDate - actual;
```

`予定` モードと `実績+予定` モードは従来どおり全予定（`plan`）を見る。手順2 の「消し込み済みかどうかに関わらず全予定を集計する（＝当初予算を保つ）」はそのままである。

当月の差異は「本日までに予定されていた分」との比較なので、`予定` モードの月合計とは一致しない。**当月の列に「9/25 時点」と注記する**（AC-43）。注記が無いと、利用者が引き算で突き合わせて「差異と予定が合わない」という別の疑問を生む。

## 理由

**規則から導かれるものを分岐で書かない。** 未来月が空になるのは、予定日が本日以前の予定が1件も無いからであって、未来月だからではない。`if (!isPast) return null` を残すと、規則と分岐の二重管理になり、片方だけ直す事故が起きる。`applyMode` にその旨をコメントで残した。

**当月を丸ごとどちらかに寄せる案では解けない。** 当月を未来扱いにすれば偽の黒字は消えるが、月の途中の予実がまったく見えなくなる。当月を過去扱いにすれば上の偽の黒字が出る。問題は月の単位で切っていることにあり、日の単位で切れば両方消える。

**予定側を絞り、実績側は絞らない。** 未来日の実績は隠さない（前払い、CSVの先日付行、そして最も多いのは日付の打ち間違い）。その帰結として、未来月に実績だけがある月は差異が全額の予定超過として出る。打ち間違いは負の差異として目立つほうが見つけやすい。

## 却下した選択肢

**`applyMode` に `today` を渡して内部で判定する。** `applyMode` はセル1つぶんの合計を受け取る関数で、その合計がどの予定インスタンスから来たかを知らない。日付での取捨は集計の段（`accumulate`）でしかできない。

**予定側そのものを本日以前で絞る。** 差異は直るが、`予定` モードが「当初予算」を出せなくなる（手順2 に反する）。面を分ける必要がある。

**実績のある月だけ差異を出す。** 未来月は空になるが、当月の未到来の予定は残るため②が直らない。また「実績が1件でもあるか」は費目ごとに違うので、月の単位の条件にできない。

## 影響

- `PLInput` に `today` が必須で加わる。core は現在日時を引数で受け取る（CLAUDE.md §2.3）
- `PLMatrix` に `planToDate` が加わる。`plan` の部分集合なので行は増えない
- `applyMode` の引数が `(mode, group, { plan, planToDate, actual }, isPast)` になる。呼び出し側が予定側を取り違えられないようにするため、3つをまとめて渡す
- `buildPLDisplay` の第3引数が年月（`YearMonth`）から本日（`DateStr`）に変わる
- `PLDisplay.asOfNote` が加わる。差異モードで当月がその年に含まれるときだけ値を持つ
- 差異の年計は「見えている値の合計」のままなので、未来月の0を足しても変わらない
