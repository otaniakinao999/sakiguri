# ADR-0044 AC-64・AC-66 の往復を、本番の保存経路で測る

日付：2026-11-15
関連：FR-58・FR-59、AC-64・AC-66、CLAUDE.md §2.5.3・§2.8・§2.11

## 文脈

`source_name`（取込時の摘要の原文）と `replace_name`（仕分けルールの
置き換え先）は、**保存されて初めて意味を持つ値**である。落ちても画面は
同じものを出し、**次に開いたときに判定だけが変わる。**

この2つは長く「実機は未」のまま残っていた。理由として
「マイグレーション 0009 の適用待ち」と書かれていたが、**3日古い記述**
だった（0009・0010 は 2026-11-12 に台帳へ入っている）。実際に残っていた
のは、**サインインした状態で本番の Supabase に書く確認**である。

`/dev/screens/live`（本番の画面を記憶上のストアに載せたページ）では
測れない。保存が `setData` までで、`diffAppData` → `saveDiff` を通らず、
**列が実在するかも分からない。**

## 判断

### 1. 負荷試験アカウントで、本番に書いて読み直す

`pnpm loadtest:roundtrip`。CLAUDE.md §2.5.3 のとおり `+loadtest` で入り、
終わったら `pnpm loadtest:teardown` で消す。

**番人を2つとも、流すたびに確かめる。**

- **アカウントの同一性。** `client.ts` は「`+loadtest` を含むか」しか
  見ない ―― **別の `+loadtest` アカウントでも通る。** だから
  `.env.local` の `LOADTEST_EMAIL` と**完全に一致する**ことを見る
- **RLS。** 見えた行の `user_id` が全部自分のものか。1行でも他人の行が
  あれば、**書く前に止める**

### 2. 手で `upsert` と `select` を書かない（§2.8）

書くのも読むのも本番の関数をそのまま呼ぶ ―― `diffAppData` → `saveDiff`、
`loadAppData`。**写し取ると、本番の保存経路を直したときにスクリプトが
古いまま残り、本番と違うものを測っていることに気づけない。**

そのために `storage.ts` と `diff.ts` の import に拡張子（`.ts`）を
足した。**この流儀はこれで3ファイルになった**（`fetch-all.ts` と合わせて）。
外されたら `pnpm check:node-import` が落ちる。

### 3. 測りたい差がそのデータで出るようにする（§2.11）

- **表示名と原文を別の文字列にする。** 同じにすると、`source_name` を
  落として `name` で代用する実装でも通る ―― `matchNameOf` が実際に
  その代用をするので、**空振りが「正しい結果」の顔で出る**
- **置き換え先を `pattern` と別の文字列にする**
- **「在ること」と「無いこと」を同じ実行で測る。** 原文を持つ実績と
  持たない実績、置き換えのあるルールと無いルールを両方入れる。片方だけ
  だと、**全部 null にする実装**とも**null を空文字にする実装**とも
  区別が付かない

走らせる前に、スクリプト自身がこの2つを検査して止まる。

## 却下した選択肢

### `rows.ts` の変換だけを呼び、`upsert` と `select` は手で書く

退けた。短く書けるが、**それは `saveDiff` と `loadAppData` を写し取る
こと**である（§2.8）。本番が列を1つ落としても、スクリプトは自分の
列挙で測り続ける。

### 書き出し（バックアップ）を先に取る

**一度はそう決めたが、やめた。** `supabase db dump` は Docker を要求し、
この端末に無い。そして保険をかける相手に経路が届いていない ――
`teardown` は RLS と `+loadtest` の検査の2つで塞がっていて、
**他の利用者の行には物理的に当たらない。** 道具を増やしてまで塞ぐ穴が
無かった（`docs/バックアップの状況.md`）。

## 影響

- **7条項が通った**（AC-64 が4つ、AC-66 が3つ）。**9通り壊して8つが割れる**
- **1つは1箇所壊しても割れない。** 「原文を持たない実績は持たないまま
  戻る」は留め具が2つある ―― `fromActual` が `null` を書き、`toActual` が
  **falsy を「無い」として扱う。** 片方だけ壊すと、もう片方が吸収する。
  **2つ同時に壊すと割れる**（§2.11「割れなかったときに分かるのは
  割れなかったことだけ」）
- `storage.ts`・`diff.ts` の import に拡張子が付いた。`check:node-import`
  の一覧に3モジュール足してある
- **行は残らない。** スクリプトは消さず、`pnpm loadtest:teardown` に
  寄せる ―― 消す経路を2つにしない
