# 0004. Tailwind をデザイントークンに束縛する

## 文脈

CLAUDE.md §2.6 は、色とサイズを `docs/designsystem.md` のトークンから引くこと、余白スケール外の中間値を作らないことを求める。`padding: 15px` も `color: #63063E` も禁止である。

しかし Tailwind の既定スケールをそのまま使うと、`p-4`（16px）も `bg-red-500` も `text-sm` も書けてしまう。これらはデザインシステムに存在しない値だが、ビルドは通り、画面も表示される。規約違反が何も起こさないまま残る。

PoC開発計画 §5 は、AI が規約を静かに破ることを繰り返し懸念している（§5.1 テストの書き換え、§5.2 丸めの省略、§5.4 RLS の忘れ、§5.9 依存の膨張）。読まれることを前提にした規約は効かない。

## 判断

Tailwind v4 の `@theme` で**既定スケールを消し、デザイントークンだけを割り当てる。**

- `--color-*` / `--spacing` / `--spacing-*` / `--text-*` / `--radius-*` / `--tracking-*` / `--font-weight-*` を `initial` でリセットする
- そのうえで `docs/designsystem.md` のトークンを名前付きで割り当てる
- トークンの定義そのものは `src/styles/tokens.css` に純粋な CSS カスタムプロパティとして置く。`@theme` はそこを `var()` で参照するだけにする
- 色はセマンティック（object / surface / border）のみ公開し、プリミティブ（`blue-100` 等）は Tailwind から引けないようにする

## 理由

**規約違反がビルド結果に現れる。** 実際に確認した。

| 書いたクラス | 生成された CSS |
|---|---|
| `p-15` | 生成されない |
| `bg-red-500` | 生成されない |
| `text-sm` | 生成されない |
| `rounded-lg` | 生成されない |
| `p-4` | `padding: var(--sp-4)` |
| `rounded-base` | `border-radius: var(--radius)` |

スケール外の値を書くとスタイルが当たらないため、画面を見た瞬間に気づく。レビュアーの注意力ではなくツールで担保できる。

トークンの一次情報は `tokens.css` に残るため、将来 Tailwind をやめても定義は生き残る。`@theme` は参照層にすぎない。

## 却下した選択肢

**Tailwind をレイアウトだけに使い、色と余白は素の CSS で `var()` を書く。** これは PoC開発計画 §2 が書いている方針である（「Tailwindはレイアウトに使う」）。トークンは守られるが、`p-4` のような既定クラスを書ける余地が残り、違反を機械的に検出できない。

@theme 束縛はこの案の**意図**（トークンを一次情報にし、Tailwind に色や余白を決めさせない）を満たしたうえで、違反を検出可能にする。上位互換と判断して採った。PoC開発計画の記述からは外れるため、ここに残す。

**Tailwind を入れず、tokens.css + プレーンCSS のみにする。** プロトタイプの CSS がほぼそのまま移植できる。ただし PoC開発計画 §2 の技術選定から外れる。

**既定スケールを残したままトークンを追加する。** `p-4`（16px）と `p-16`（16px）が両方存在する二重の語彙ができる。どちらで書いてもよくなり、実質的に規約が無くなる。最も避けたい状態。

## 影響

**余白クラスの数値はトークン名＝px値と一致する。`p-16` は 16px であり、Tailwind 既定の 64px ではない。** これは意図的だが、Tailwind の既定値を前提にした知識・既存スニペット・生成コードはそのままでは合わない。移植時に読み替えが要る。トレードオフとして受け入れる。

- 角丸は `rounded-base`。Tailwind v4 は素の `rounded`（`--radius-DEFAULT`）を解釈しないため、明示的な名前で公開している
- `p-0` のために `--spacing-0: 0px` を明示的に定義している。`--spacing` を消すと動的スケールごと消えるため
- 色はセマンティック名で書く（`text-object-error-dim`、`bg-surface-accent-subtle`）。長いが、`error` が purple であること（designsystem.md §1.3）を書くたびに思い出せる
- 新しいトークンが要るときは `docs/designsystem.md` → `tokens.css` → `globals.css` の順に足す。逆順に足さない
