# ADR-0031 やることと実績一覧を別のページにする

2026-11-12 ／ FR-54・AC-61

## 文脈

SC-05 実績入力は1つのページに2つのパネルを縦に並べていた。

- **やること** ―― 消し込まれていない予定と、照合されていない実績
- **実績一覧** ―― 記録済みの実績。月タブとページング（AC-28）

やることを片付けているあいだも、下に長い一覧が付いている。逆に、記録済みの
実績を直したいときは、やることを越えて下まで送ることになる。

## 決めたこと

**`/entry`（やること）と `/actuals`（実績一覧）に分ける。**

| | 置くもの |
|---|---|
| `/entry` 実績入力 | やること（予定の消し込み・**照合の候補**）、手入力、繰延 |
| `/actuals` 実績一覧 | 月タブ、口座の絞り込み、編集・削除 |

**照合はやること側に置く。** 未照合の実績を予定に結びつけるのは、やることを
片付ける操作である。

**手入力もやること側。** 要件定義書 §4.1.1 が「要対応リストを主とし、手入力は
ボタンからモーダルで開く」と定めている。

**一覧は実績を選り分けない。** 照合の導線が消えても、未照合の実績はこの一覧に
出る。**どちらからも直せない実績を作らない**（AC-61）。

## 理由

目的が違う。やることは**片付ける**画面で、件数が0に近づくのが正しい。
一覧は**探して直す**画面で、件数は増え続ける。同じページに置くと、片方の
長さがもう片方の邪魔をする。

## 却下した選択肢

| | なぜ却下したか |
|---|---|
| タブで切り替える | 1つのページのままなので、ブラウザの戻る・リンクの共有が効かない。サイドバーにも出ない |
| 一覧を折りたたむ | 畳んだ状態を覚えるかどうかが新しい問題になる。畳んでいると一覧があること自体に気づけない |
| 照合を一覧側に置く | 未照合の実績は「やることが残っている」状態である。片付ける側に置かないと、やることの件数が実態より少なく見える |
| 一覧を未照合だけに絞る | **照合済みの実績を直せなくなる。** 一覧の目的は探して直すことで、照合の状態で選り分ける理由が無い |

## 影響

- 画面の一覧（`NAV_ITEMS`）が6件から7件になる。**画面IDは SC-05 を共有させた**
  ―― 要件定義書 §4.1 の画面一覧はまだ1行である（仕様側の更新が要る）
- `EntryView` が持っていた行の型は `entry/rows.ts` へ出した。ページを分けた
  あとに一覧側が「やることの画面」を import する形にしないため
- やることの末尾から一覧へのリンクを置いた。サイドバーだけだと、実績を直し
  たくなった利用者がこの画面から辿れない
- **残高サマリーの計算の並べ方は他の画面と同じ**（CL-1 → CL-3 →
  `buildHeaderStats`）。この画面で7つめになる。**同じ形が7箇所にある**のは
  §2.8 が言う重複だが、ここだけ別の経路で出すと同じ「現預金 見込み」が画面
  ごとに違う計算から出る（§2.12）。**揃えるなら7箇所まとめて**であり、
  この変更には混ぜない
