# 0020. 年月別収支の表示モードから期間の場合分けをなくす

ADR-0019 を完成させる。0019 の判断は正しかったが、**適用が片側で止まっていた。**

## 文脈

ADR-0019 で差異モードの予定側を「発生日が本日以前」に絞り、`if (!isPast) return null` と当月の場合分けを削除した。当月の偽の黒字（3費目が予算超過なのに収支 +14,800）は消えた。

しかし実績側を絞らなかったため、10月に未来日の実績125,000を置くと差異が **−125,000**（予算超過）と出た。

| | 予定側 | 実績側 |
|---|---|---|
| 元の欠陥 | 月全体 | 月途中まで |
| 0019 のあと | 本日まで | **月全体** |

向きが逆になっただけで、**両辺の期間が揃っていない**点は変わっていない。差異モードは予実を判断する画面であって、入力ミスを探す画面ではない。未来日の実績には正当なもの（CSVの予約振込行など）もあり、それを「予算超過」と表示するのは誤りである。

同じ構造が `実績+予定` にも残っていた。手順6 は「過去月は実績、未来月は予定」としか書いておらず当月を決めていない。当月を実績側に置くと月初がほぼ空になり、予定側に置くと入力済みの実績が無視される。**当月をどちらに置くかを決めようとしている限り、どちらかの誤りを選ぶことになる。**

## 判断

4つのモードそれぞれに、**期間の場合分けを持たない定義**を与える。

| モード | 定義 | 一次情報 |
|---|---|---|
| `予定` | 全予定インスタンス | 手順2（当初予算を保つ） |
| `実績` | 全実績 | 手順3 |
| `差異` | **両辺とも発生日が本日以前** | AC-42 |
| `実績+予定` | **発生日が本日以前の実績 ＋ 未消し込みの予定インスタンス** | AC-44 |

`PLMatrix` は5つの面を持つ。`applyMode` はどの面を見るか（または2面の差を取るか）を決めるだけで、**引数に期間を取らない。**

```ts
export function applyMode(mode, group, values): Yen | null {
  switch (mode) {
    case "plan":   return values.plan;
    case "actual": return values.actual;
    case "mixed":  return values.outlook;
    case "diff":   return group === "income"
      ? values.actualToDate - values.planToDate
      : values.planToDate - values.actualToDate;
  }
}
```

`PLDisplay.isPast` も削除した。表示モデルが過去月・未来月という区別を持たない。

## 理由

**両辺の期間を揃える。** 差異が意味を持つのは、同じ期間の予定と実績を比べたときだけである。片側だけを絞ると、絞った側が小さく出るぶんだけ差異が一方向に偏る。0019 ではそれが「未来月の予算超過」として現れた。

**「当月をどちらに置くか」は解く必要のない問題だった。** 両方に置けばよい。`実績+予定` を「本日までの実績 ＋ 未消し込みの予定」と定義すると、月初は予定に近く、月末は実績に近づき、月の境界に段差が生まれない。過去月は全部消し込み済みなら実績のみ、未来月は予定のみになり、手順6 の記述はこの定義の特殊な場合として導かれる。

**CL-3 と同じことを言うようになる。** 未消し込みの過去予定を予定額のまま残すのは CL-3 の予測系列の方針そのものである。実機で確認した（本日 2026-09-26）。

| | CL-3 入出金予定表 2026年9月 | CL-5 実績+予定 2026年9月 |
|---|---|---|
| 入金 | +535,000 | 収入 535,000 |
| 出金 | −190,000 | 固定費 182,000 ＋ 変動費 8,000 |
| 収支 | 345,000 | 345,000 |

出金の内訳も一致する。実績（120,000・25,000・3,000・7,000）に、要対応リストに出ている未消し込みの2件（電気代（変動）5,000・固定資産税30,000）が足されている。**残高予測と年月別収支が「見込み」について同じことを言う。** 食い違うと、利用者が気づいても説明できない。

**未来日の実績の検知は別の仕組みで扱う（OI-21）。** 実績一覧が月単位になったので、未来の月タブが現れるのが当面の発見経路である。損益の画面でそれを兼ねさせない。

## 却下した選択肢

**差異の実績側だけを絞り、`実績+予定` は当月の扱いを決めて済ませる。** 当月を実績側に置けば月初がほぼ空、予定側に置けば入力済みの実績が無視される。どちらも誤りで、月の単位で切っていることが原因である。

**`実績+予定` の予定側も本日で絞る。** 未来月が空になる。このモードは見通しを出すためのものなので、未来月に予定が出ないのでは用をなさない。絞るべきは実績側だけで、予定側は「未消し込みかどうか」で絞る。

**面を持たず、モードごとにイベント列をフィルタして集計し直す。** 面が5つあるのは冗長に見えるが、行の並びを5面で揃える必要がある（片方にしか出ない費目も0の行として残す）。集計を分けると並びも別々に作ることになる。

## 影響

- `PLMatrix` が `plan` / `actual` / `planToDate` / `actualToDate` / `outlook` の5面を持つ
- `applyMode` の引数が `(mode, group, values)` の3つになる。**期間を受け取らない**ことが、場合分けを足せないことの保証になっている
- `PLDisplay.isPast` を削除
- `実績+予定` の「予」の注記は、**見込みと当初予算が違う月にだけ**出す。期間では出し分けない
- `実績+予定` の当月は「本日までの実績 ＋ 未到来の予定」になるため、月初は予定寄り、月末は実績寄りの値になる。注記が要るかは画面を見て判断する
