# ADR-0025 振替を両側の明細から記録できるようにする

- 状態：採用
- 日付：2026-11-10
- 対象：CL-3 / CL-6 / CL-7、FR-18、AC-20c

## きっかけ

利用者の要望「データ登録する前に事前に収入・支出・振替を設定したい」。
仕分けルール（FR-18）を設計するときに、**取込では振替を作る手段が1つも無い**
ことが分かった。

```ts
const type: EntryType = signed > 0 ? "income" : "expense";
```

収支は金額の符号だけで決まり、`ImportRow` は `toAccountId` を持たない。
費目マスタでも TRF-01 口座間振替は「手動」である。

## 何が問題か

**振替は片側のCSVにしか載らない。** ○○銀行から△△信金へ10万を移すと、
○○銀行の明細には出金10万、△△信金の明細には入金10万が、別々に出る。

ルールで○○銀行側を「`type = transfer`・振替先は△△信金」にすると、
**その時点で△△信金の残高が10万増える**（CL-3 手順6）。そのあと△△信金の
CSVを取り込むと、入金10万がもう一度乗って**二重計上**になる。

**FR-50 の重複検出では捕まらない。** 口座も収支も摘要も違うからである。

相手側の行を自動で外す案は、摘要が両行で違うので**口座・日付・金額・向きだけで
当てる**ことになる。これは FR-50 で「**ゆるく当てると本物のデータが落ちる**」と
決めたばかりの方針と正面からぶつかる。

## 決めたこと

**`type` を変えずに、費目だけを資金移動（TRF）にする。**

- ○○銀行側：`type = expense` ＋ 費目 TRF-01（口座間振替）
- △△信金側：`type = income` ＋ 費目 TRF-01

どちらも**自分の口座の明細から**作られる。`toAccountId` は誰も設定しない。

| 見るもの | どうなるか |
|---|---|
| 口座別の残高 | ○○銀行 −10万、△△信金 +10万。どちらも自分の明細どおり |
| 合計残高 | 両方を取り込めば ±0 |
| 年月別収支（CL-5） | **出ない。** `plGroupOf` は費目の判定が先で、TRF は `null` を返す |
| 入出金予定表のフィルタ | 「振替」に掛かる。`matchesKind` が TRF グループ全体を見ている |

**ゆるい一致を1つも使わない。** 相手側を探さないので、探し損ねも、
本物のデータを外すこともない。

### この形は新しくない

`type = expense` の資金移動は**既にこの仕組みの中にある。**
カード引落（TRF-04）と借入返済の元金（TRF-06）がそれで、`lib/ledger.ts` の
`matchesKind` が「`type = expense` の資金移動」と名指しで扱っている。

止めていたのは仕様ではなく UI で、`ui/inputs.tsx` の `categoryGroupFor` が
`type` から費目グループを1対1で写している。**要件定義書の適用規則は
「TRF は CL-5 の対象外・CL-3 には含める」しか言っていない。**

## 失うもの：月次資金繰り表に出る

`buildMonthlyCashflow` は**費目を一切見ない。** 入出金は口座の増減（delta）
だけで決まる。コードにも「この1本で両方が出る。場合分けを足さないこと」と
書いてある。

したがって両側記録では、合計スコープで**入金10万・出金10万が立つ。**
1行の振替（`type = transfer`）なら合計で相殺されて0になり、立たない。

**AC-20c「口座間振替が月次資金繰り表の出金に含まれないこと」と衝突する。**

### それでも採る理由

**AC-20b が既に同じことを認めている。**

> カード引落と借入返済の元金が、月次資金繰り表の出金に含まれること（CL-6）

これらは `type = expense` の TRF 行である。つまり**「TRF の行は出金に出る」が
既定で、1行の振替だけが相殺で例外になっていた。** 両側記録は例外のほうを
使わないだけで、新しい振る舞いを持ち込まない。

**費目で外す直し方は採らない。** 口座別スコープでは送金元の出金として
出したいので、費目で外すと口座別からも消える。delta 一本で合計と口座別の
両方を出しているのが今の作りで、そこに場合分けを足さない。

### 残る不揃い

同じ移動が、**手で1行の振替にすると出金に出ず、両側記録にすると出る。**
記録の仕方で月次表の見え方が変わる。

**1行の振替は残す**（既存データがあり、口座をまたぐ移動を1操作で入れたい
場面もある）。**ただし取込が作るのは両側記録だけ**とし、どちらを使うかは
利用者の入力手段で決まるようにする。

## 決めなかったこと

**2行が同じ移動だと app に教える仕組みは作らない。** 作るなら候補を出して
人が確定する形（FR-46 と同じ）になるが、**いま要るものではない。**
合計も口座別も損益も正しく出るので、結びつけが無くても困らない。

## 影響

- `categoryGroupFor` の1対1の写しを外す（TRF はどちらの符号でも選べる）
- 適用規則に「費目グループと `type` の対応」を書く
- **AC-20c を書き直す**（1行の振替についての規則として残す）
- AC-58 を足す（支出の行が TRF の費目を持てること）
