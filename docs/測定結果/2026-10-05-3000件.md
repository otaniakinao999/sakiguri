### 読み方

**`actuals` が3往復**なのが要点。1,000件の上限を2回またいでいる。またいだうえで、受取3,000 = ユニーク3,000 = 総件数3,000 で、並びの逆転が0。

**`overrides` は40件。** `plan_key` が並び替えキーなので、ここに行があって初めて「全テーブルで一意」が確かめられる。40件は定期項目1〜20 × 2ヶ月（2026-03 / 2026-06）で、`(定期項目id, 発生日)` の組が重複しない。繰延20件（`date` を5日後に差し替え）と金額変更20件の両方を含む。

**残る弱さが1つある。** `seed.ts` は `plan_key` を**組み立てている**（`r:{id}:{発生日}`）。`forecast.ts` の `recurringKey` を import できないため（`./date` を拡張子なしで import していて Node が解決できない）。形式を変えると AC-50 のテストは落ちるが、**`seed.ts` は落ちない。** そのとき `seed.ts` は古い形式のキーを作り続ける。
