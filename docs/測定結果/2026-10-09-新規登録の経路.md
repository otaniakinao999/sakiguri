# 2026-10-09 ／ 新規登録の経路（AC-51・AC-52・AC-53）

対象：`otani.akinao+loadtest-ac51@showtime.design`（使い捨て。確認後に削除する）
送信先の戻り先：`https://sakiguri.vercel.app/auth/confirm`（`emailRedirectTo`）

**確認メールの送信は1回だけ。** 既定の送信は1時間あたり数通で制限されるため（`docs/新規登録の経路.md`）。

---

## 1. 新規登録（AC-51 の機構）

```
宛先          otani.akinao+loadtest-ac51@showtime.design
emailRedirectTo https://sakiguri.vercel.app/auth/confirm
error         なし
user          返った
identities    1  ← 新規なら1、既存なら0
session       返らない（確認待ち）
```

**`identities` が 1。** 新規のアドレスであることが応答から分かる状態。**アプリはこれを見ていない**（`signUpNotice()` は引数を取らない）。

## 2. そのままサインイン（AC-53 の機構）

```
error         400 email_not_confirmed Email not confirmed
session       返らない
```

**確認前はサインインできない。** 専用のコード `email_not_confirmed` が返るので、`signInFailure` が専用の文面に分岐する。

## 3. 既に登録済みのアドレスで新規登録（**AC-51 の核心**）

同じアドレスで、もう一度新規登録を試した画面。

```
このメールアドレス宛に確認メールをお送りしました。
メールのリンクを開いて登録を完了してください。
メールが届かない場合は、すでに登録済みの可能性があります。
  [サインインする] [パスワードを再設定する]
```

**新規のときと同じ文面。** 「すでに登録されています」も「登録しました」も出ない。導線2つが**同じ場所**にある。

これが AC-51 がいちばん守りたい性質である。**サインイン画面で塞いだ穴が、新規登録画面に開いていないこと。**

## 取り逃がしたもの

### AC-53「確認が済んでいない」の画面

**取れなかった。** アカウントの作成から確認まで **26秒**だった。

```
created_at    2026-10-08T23:27:41Z
confirmed_at  2026-10-08T23:28:07Z
```

手順2（API での確認）を終えて画面を開いた時点では、もう確認済みになっていた。ローカルでサインインすると**そのままアプリに入った。**

**機構は取れている**（上の2。`400 email_not_confirmed`）。文面も `auth-messages.test.ts` で固定してある。残っているのは**その文面が画面に出ることの目視だけ。**

埋めるには、新しいアドレスで1通送って、**確認する前に**サインインを試す必要がある。
